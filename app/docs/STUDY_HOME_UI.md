## 구현 범위

리더·스터디원 홈, 선택한 스터디·역할 유지, 공지·과제 현황, 알림 목록과 읽음 표시, 해당 내용으로 이동한다. 서버 통신 없이 목 데이터와 로컬 상태를 사용한다. 새로고침·로그아웃·시나리오 재선택 시 목 상태를 초기화한다.

공지·과제 탭과 상세는 홈·알림의 이동 대상을 확인하기 위한 최소 목록/읽기 화면이다. 전체 공지·과제 시안, 작성·수정·제출, 스터디 설정은 이번 일치 판정에 포함하지 않는다. 멤버 탭은 기존 후속 이슈 안내 화면을 유지한다. 헤더 메뉴의 알림·내 스터디 링크는 이번 이동을 위한 보조 UI이며 별도 Figma 메뉴 시안과 일치했다고 판정하지 않는다.

알림 선택 시 해당 알림만 읽음 처리한다. 공지 상세를 열면 해당 스터디 공지를 읽음 처리하고 스터디원 홈에서 제거한다. 과제 상세를 열어도 제출 상태는 바뀌지 않는다. 이는 API 연결 전 시연 가정이며 알림 점/읽음의 서버 정책을 확정한 것이 아니다.

## 실행 검증

- 리더 홈 기본 상태: 공지2/과제1, 2/4 읽음·1/4 제출 표시.
- 스터디원 홈 기본 상태: 읽지 않은 공지1/과제1, 배너 할 일2건.
- 공지 상세 열기 → 뒤로가기: 읽지 않은 공지가 사라지고 할 일1건. 과제 상세 열기만으로 미제출 상태는 변하지 않음.
- 현황 공지 카드 → 공지 목록 → 홈 탭 복귀.
- 목록에서 알고리즘 선택: 홈 헤더가 알고리즘으로 바뀜. 그 상태에서 프론트엔드 알림 선택: 프론트엔드 공지 내용으로 이동.
- 알림 선택 → 상세 → 뒤로가기: 선택한 알림의 점만 사라짐.
- 공지/알림을 읽고 로그아웃 → 목 로그인 → 알림: 초기 미읽음2개 복원. 검토 중 발견한 로그아웃 읽음 상태 잔존을 수정하고 재실행.
- 빈 스터디 시나리오 → 알림: 빈 안내. 새 스터디 생성 → 홈: 선택 이름 유지, 현황0/0과 빈 안내.
- 320px 화면: 가로 넘침·겹침을 확인하고 웹 한글 단어 단위 줄바꿈을 적용. 이 폭은 별도 Figma 시안이 없으므로 반응형 동작 검증이다.

## 증거와 판정 범위

`evidence/321`의 `figma-*.jpg`는 Figma 편집기 원본 캡처이고, `leader.jpg`, `member.jpg`, `notifications.jpg`는 구현 캡처다. `*-after-read.jpg`, `notifications-logout-reset.jpg`, `home-empty.jpg`, `notifications-empty.jpg`는 상태별 증거다. 초기 캡처보다 늦은 코드 변경이 있을 때 기본 상태는 다시 촬영한다.

| 항목 | 판정 |
| --- | --- |
| 리더/스터디원 기본 홈·알림의 확인한 치수, 타이포그래피, 색상, 원본 아이콘 | 검사 패널과 웹 속성/실행 화면을 비교하여 확인된 불일치 수정 |
| 새로 추가한 빈 상태·메뉴·읽기 대상 화면 | 동작 검증. 별도 시안이 없어 시각적 일치 판정 제외 |
| 픽셀 단위 전체 일치율 | 미산정. Figma 축소 편집기 캡처와 웹 viewport의 배율/영역이 다르므로 임의 확대·가림으로 점수를 만들지 않음 |
| iOS/Android 실기기·시뮬레이터 | 미검증. 로컬 simctl 실행은 exit72로 실패. 웹 성공과 네이티브 실행 성공을 구분 |
| 네트워크·실제 로그인·푸시·OS 권한 | 범위 제외 |

타입 검사와 Biome check를 실행한다. Biome 설정은 rule preset none이므로 스타일/정렬 검사를 전체 코드 안전성 검증으로 해석하지 않는다. Expo web/iOS/Android JS·에셋 export는 성공했으나 네이티브 바이너리 빌드나 기기 실행을 의미하지 않는다.
