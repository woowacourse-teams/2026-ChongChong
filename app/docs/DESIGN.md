# 총총 앱 디자인 기반

## 1. 분위기와 기준
Design ver2의 흰 배경, 초록 강조, 얇은 카드 테두리를 따른다.
기준: https://www.figma.com/design/sT7K2tOQl8JtyHzuwT0nnl?node-id=1702-18637
화면 크기 390×844와 본문 여백 20은 Figma에서 확인했다.
색상·글꼴은 Computer Use로 Figma 변수 패널을 직접 확인했다.
버튼·입력창 반경 12와 모달 반경 20은 Dev Mode에서 직접 확인했다.

## 2. 색상
배경 #FFFFFF, 보조 배경 #F9F9F9, 브랜드 #00C471, 브랜드 배경 #E6F9F0.
본문 #172033, 보조 본문 rgba(15,23,42,0.7), 테두리 rgba(15,23,42,0.08), 오류 #DE5E56.
강조 버튼 글자는 시안의 #FFFFFF를 사용한다.
비활성 버튼 배경 rgba(15,23,42,0.40), 버튼 글자 #FFFFFF, 모달 배경 rgba(0,0,0,0.42). 원본 변수 background/muted(6%)와 text/disabled(32%)도 보존하지만 비활성 버튼에는 적용하지 않는다.

## 3. 타이포그래피
Pretendard Regular/SemiBold를 로컬 OTF로 로드한다. 라이선스는 assets/fonts/LICENSE.
제목 24/34, 소제목 18/28, 큰 본문 16/24, 본문 14/20·13/18, 설명 12/18·12/16. 자간은 크기의 -2.5%를 사용한다. 공통 화면은 Regular를 기본으로 사용한다.
접근성 글자 확대를 허용한다. 보드 설명용 36/64·48/64는 앱에서 사용하지 않는다.

## 4. 간격과 레이아웃
간격 4·8·12·16·20·24·32·40. 페이지 좌우20, 카드 내부20. 버튼·입력·토스트 수직 패딩14와 배지5/10은 별도 공통 토큰으로 관리한다.
반경 8·12·16·20·999. 뒤로가기 터치 영역48, 헤더 아이콘24, 하단 탭 아이콘22, 기본 테두리1을 사용한다. 모든 터치 영역이48 이상인 것은 아니다.
화면은 Safe Area를 사용하고 본문 ScrollView가 스크롤을 소유한다.
태블릿·웹 확인 화면은 최대 폭 600으로 제한하고 가운데 배치한다.
키보드는 KeyboardAvoidingView로 대응한다. 탭은 본문 바깥에서 고정한다.

## 5. 공통 컴포넌트
- AppText: 본문·제목·설명 크기, 색상 의미와 굵기 지정.
- Button: 강조·보조·위험, 눌림 opacity 0.7, 비활성·로딩. 버튼 역할과 상태 제공.
- Field: 라벨·입력·오류, 입력 접근성 라벨, 오류 문구 표시.
- Card/Badge: 본문 그룹과 역할 표시. 카드 자체는 비대화형.
- EmptyState: Figma 원본150px 이미지와16/24 안내 문구로 빈 화면 설명.
- ConfirmDialog: 제목·설명·취소·확인. Android 뒤로 가기로 취소, 접근성 modal.
- Toast: 브랜드 배경·흰색 체크 아이콘·14/20 메시지와 live region. 토스트를 누르면 닫히며 자동 소멸하지 않아 읽을 시간 보장.
- Screen: Safe Area·키보드·본문 스크롤 공통 처리.
버튼은 최소 높이 52·반경 12·16/24 텍스트, 입력창은 수직 패딩 14·수평 16·반경 12와 초록 포커스 테두리를 사용한다. 모달은 최대 폭 310·반경 20이다.
공통 UI 확인 화면에서 위 컴포넌트를 조작한다. 실제 제품 화면은 후속 이슈 범위다.

## 6. 인터랙션
기본 네이티브 스택·탭 이동을 사용한다. 별도 장식 애니메이션은 추가하지 않는다.
선택 상태는 색상뿐 아니라 역할 문구와 accessibilityState로도 표시한다.

## 7. 표면
흰 카드·반경16·1px 안쪽 테두리, 브랜드 배경 역할 배지·토스트로 구분한다. 장식 그림자 없음.

## 8. 접근성과 검증 제약
글자 확대, 라벨과 오류 텍스트, disabled/busy 상태를 제공한다. 뒤로가기 터치 영역은48이며 웹 하단 탭은88×44다. Figma 탭의 콘텐츠 높이도44이므로 이를 시안 불일치로 판정하지 않는다. Figma의 시각적 레이아웃만으로 전체 터치 영역의 접근성 기준 충족을 보장하지 않는다.
웹은 보조 확인 수단이며 iOS·Android 실기기 검증을 대체하지 않는다.
OS 화면 읽기·키보드·실제 Safe Area는 네이티브 실행 환경에서 후속 검증해야 한다.

## 9. 직접 확인한 노드
- 버튼: `1702:19700` (스터디 만들기).
- 포커스 입력창: `1702:19693` (350×54: 내용316×24, 좌우 패딩16·상하14·테두리1씩).
- 안내 모달: `1702:18659` (310px 폭, 반경 20, 흰 배경, 기본 테두리).
안내 모달의 외형을 공통 확인 모달에 적용하고 삭제 모달의 두 동작 배치를 별도로 대조했다. 카드·배지·토스트·빈 상태까지 브라우저 Figma로 검증한 최신 기준은 UI-VERIFICATION.md에 기록했다. 실제 기능 화면의 배치와 데이터 연결은 후속 이슈다.

## 10. 하단 탭 아이콘
Computer Use로 스터디 홈 `1702:19610`의 22×22 아이콘을 대조했다. Feather 대체 아이콘을 제거하고 기존 `frontend/src/shared/assets`의 home/notice/assign/user SVG와 green 변형의 path를 `StudyTabIcon`으로 이식한다. 네이티브 SVG로 렌더링하며 선택 색상은 브랜드, 비선택은 text/placeholder(40%)를 사용한다. 비선택 라벨은 text/tertiary(55%)로 아이콘과 구분한다. 탭 바는 64px에 기기 하단 Safe Area를 더하고 상단12·하단8 여백을 적용한다. 아이콘22·간격4·라벨18로 구성하며, 테두리는 배경에 그려 라벨 높이를 줄이지 않는다. 390px 폭에서 아이콘 중심은63·151·239·327이다. 균등 터치 영역88과 바 수평 여백19로 시안의 아이콘 좌우 여백52·아이콘 사이 간격66을 만든다.

## 11. 멤버 선택 상태와 확인 모달 보정
멤버 탭은 비선택 원본 도형을 선택 상태에도 유지하고 색상만 변경한다. 기존 user-green은 별도 도형이라 탭 선택에 사용하지 않는다. 확인 모달 제목은 18/28 Regular·자간 -0.45, 설명은 14/20·자간 -0.35, 본문 패딩은 상단24/나머지20이다. 두 동작 사이에 기본 테두리 세로선을 표시한다. 일반 확인과 위험 동작은 confirmLabel/destructive 속성으로 구분한다. 쇼케이스 삭제는 목 동작이며 실제 데이터를 삭제하지 않는다.

2026-09-14 재검증: Computer Use에서 선택한 스터디 삭제 모달 `1702:18776`은310×173이다. 같은 문구로 웹에서 본문120·동작52·구분선1을 측정했다. 외곽 테두리는 절대 배치로 안쪽에 그려 본문 폭과 전체 높이에 더해지지 않는다. 전체 높이를188로 강제하지 않는다. 추가로 선택된 Actions `1702:18781`에서310×52·패딩0, 취소색 placeholder40%·삭제색#DE5E56을 읽었고 최신 웹 측정도 일치했다. 전체 공통 UI의 완전 일치는 별도 검증이 필요하다.

## 12. Figma 변수 컬렉션
`src/ui/figmaVariables.ts`는 Computer Use로 확인한 두 컬렉션의 경로와 값을 보존한다.
- 총총 v2: 색상24개와 spacing3개.
- 총총 v2 Typography: family1개, size8개, line-height7개.
`tokens.ts`는 이 원본 값에 대한 앱용 별칭이다. 자간은 컬렉션 변수가 아닌 텍스트 스타일 속성이다. 보드·소셜 변수도 보존하지만 해당 화면을 만들기 전까지 제품 화면에 임의 적용하지 않는다.

## 13. 공통 헤더
Computer Use로 선택된 헤더 `1702:19688`의 레이아웃을 재확인했다. 390px 기준 상하 패딩18, 왼쪽20, 오른쪽 spacing-3(12), 요소 간격 spacing-2(8), 내용 높이28로 전체 높이는64다. 제목은 18/28 Regular 및 자간 -0.45를 적용한다. 아이콘은24px이고 제목 시작점은 x52다. 48px 뒤로가기 터치 영역은 24px 레이아웃 슬롯 바깥으로 확장해 정렬을 유지한다. 상단/좌우 Safe Area는 헤더에서 처리한다. 루트에는 뒤로가기를 표시하지 않으며 스터디명·역할·메뉴는 후속 이슈에서 연결한다.

## 14. 브라우저 Figma 재검증
브라우저에서는 레이어 선택이 정상 동작한다. 제목 `1702:19691`의18/28·Regular400·자간-.45·primary와 버튼 제목 `1702:19701`의16/24·Regular400·자간-.4·white를 직접 읽었다. 비활성 버튼 `1702:19718`은 배경placeholder40%와 흰 글자로 수정했고 웹에서도 높이52와 해당 색상을 확인했다. 오류 문구 `1702:19735`는12/18·Regular400·자간-.3·error다. 오류 시안은 포커스 입력 테두리가 초록이므로 error에 따른 빨간 테두리 덮어쓰기를 제거했다. 웹 길이 초과 입력에서도 초록 테두리와 빨간 오류 문구, 저장 비활성 상태를 확인했다.

## 스터디 홈·알림 (#321)

역할별 홈 및 알림의 프레임별 치수, Figma 노드, 이미지 출처와 검증 범위는 [STUDY_HOME_UI.md](STUDY_HOME_UI.md)를 따른다. 공통 토큰을 재사용하고, 전역 변수로 확인되지 않은 프레임 배치값은 `src/features/home/layout.ts`에 한정한다. 상세 공지·과제 작성 흐름과 스터디 설정은 후속 이슈 범위다.

## 공지 (#323)

Computer Use로 Design ver2 공지 목록·요약·삭제 모달·작성·날짜/시간 시트·스터디원 읽음/비대상 상태를 확인했다. 목록 카드 350×168·반경16·테두리1, 간격12, 원본 썸네일80×80을 사용한다. 목록 제목은 Pretendard Regular16/24, 요약·상세 제목은 SemiBold24/34(노드1702:20782), 상세 본문16/24(노드1702:19378·20842), 설명12/18이다. 대상자 카드는 높이77·반경12·패딩20·아이콘28이다. 색상은 기존 총총 v2 변수를 따른다.

새 공지 컴포넌트는 목록 카드, 역할별 상세/요약, 대상자 상태, 이미지 첨부 목록, 리마인드 날짜/시간 시트다. 스터디원은 본문과 이미지 영역의 세로 스크롤 끝까지 도달하면 읽음 처리하며 비대상 공지는 처리하지 않는다. 리더 상세 열람은 대상자의 읽음 수를 바꾸지 않는다. 이미지 파일 선택은 Expo ImagePicker로 로컬 URI만 보유하고 서버에 업로드하지 않는다. 공통 모달·토스트·헤더·탭을 재사용한다. 상태 및 추가 검증 근거는 NOTICE_UI.md에 기록한다.
