공통 `총총 v2` 색상·Typography 토큰을 재사용했다. 로그인 제목은 Pretendard SemiBold 24/34, 나머지 본문은 Pretendard Regular를 사용한다. 소셜 버튼 350×56, 목록 카드 350×148, 입력 54, 설명 입력 96, 기본 버튼 52, 확인 모달 너비310을 기준으로 구성했다. 화면 여백·헤더·원본 아이콘을 웹 캡처와 시각 대조하여 수정했다.

Figma 프레임은 390×844이며 OS 상태바47·홈 영역34를 포함한다. 웹 기본 비교는 이를 제외한 390×763에서 수행했다. Figma 캔버스 캡처는 61% 확대 상태여서 동일 픽셀 조건의 이미지 diff나 100% 픽셀 일치 판정은 하지 않았다. OS 영역을 웹에 가짜 UI로 그리지 않는다.

## 시연 가정과 제외 범위

- 스플래시는 글꼴 로딩 뒤 1.2초 동안 표시한다. 소셜 버튼 세 개는 같은 목 진입 흐름으로 연결한다.
- 로그인 버튼 → 알림 안내 → 스터디 목록 순서는 시연 가정이다. 실제 인증·회원가입·권한 API는 호출하지 않는다.
- 이름은 8자, 스터디 이름은 15자, 설명은 30자를 넘으면 오류와 비활성 버튼을 표시한다. 공백 이름은 제출할 수 없다.
- 생성·참여·프로필·알림은 메모리만 변경하며 새로고침하면 초기화한다. 초대 참여 화면에는 시안대로 URL 입력 필드를 만들지 않았다. 고정 초대에 두 번 참여해도 중복 카드가 생기지 않는다.
- 사용자 요구 변경: 내 스터디 목록과 빈 상태의 `스터디 참여하기` 버튼을 제거했다. 초대 링크를 열면 참여 화면에 직접 진입하는 흐름이다. 현재 웹 시연 링크는 `http://localhost:8081/join-study`이며, 실제 초대 코드 조회·검증과 운영 도메인의 앱 연결은 통신 작업에서 구현한다. 이 부분은 기존 Figma 목록 시안보다 최신 사용자 요구를 우선한다.
- 리더 탈퇴 제한 모달은 시안에 따른다. 스터디원 탈퇴 확인 문구·완료 후 로그인 이동은 목 시연용 동작이다.
- 개인정보처리방침·지원의 운영 목적지는 미확정이므로 준비 중 안내를 표시한다. 실제 탈퇴·로그아웃·OS 알림 요청·푸시·API·배포는 수행하지 않는다.
- 알림 목록, 스터디 홈·공지·과제·멤버의 기능 UI는 후속 이슈 범위다.

## 실행과 재현

```sh
cd app
pnpm web
```

`http://localhost:8081/`에서 진입한다. `/scenarios`는 개발 검증 전용 메뉴로 리더·스터디원·빈 상태를 선택할 수 있다. 제품 화면에는 역할 전환 버튼을 추가하지 않았다. `/showcase`에서 기존 공통 UI를 확인할 수 있다.

## 웹 동작 검증

Computer Use로 실제 웹 UI에 입력하고 클릭했다.

- 스플래시 로고 표시 후 로그인 이동; 각 경로 직접 진입 시 스플래시 타이머가 간섭하지 않도록 수정.
- Kakao·Google·Apple 세 버튼, 알림 안내의 나중에·알림 허용, 마이페이지 토글 상태 연결.
- 목록·빈 상태, 생성 이름16자·설명31자 오류/버튼 비활성, 정상 생성 후 카드 추가.
- 빈 상태에서 초대 참여 후 스터디원 카드 추가, 반복 참여 후 카드1개 유지.
- 이름9자 오류, 정상 이름 저장과 입력 공백 제거, 저장 토스트 닫기.
- 리더 탈퇴 제한 단일 확인 모달, 스터디원 탈퇴 취소·확인 및 로그인 복귀.
- 로그아웃 시 탐색 스택 정리, 마이페이지 닫기, 생성 뒤로가기.
- 카드 → 기존 스터디 골격 → 멤버 탭 → 뒤로가기에서 역할과 목록 연결 확인.
- 320×640에서 로그인·모달·목록·계정을 추가 확인. 긴 카드 제목은 말줄임 처리하고 계정 화면은 세로 스크롤한다. 390 외 화면은 Figma 직접 대조가 아닌 반응형 동작 확인이다.

수정한 시각 차이: 목록 상단20px, 빈 상태 상하 여백, 카드148px 내부 간격, 참여 카드 간격, 헤더 메뉴32px 및 알림 아이콘, 계정 최대 본문 폭600px.

## 명령 검증 및 네이티브 제한

- TypeScript `tsc --noEmit`: 통과.
- Biome 변경 파일 검사: 통과. 기존 preset:none 때문에 실질적인 린트 규칙 검증으로 해석하지 않는다.
- Expo `export --platform all`: 웹·iOS·Android 번들 생성 성공. 네이티브 앱 바이너리 빌드나 실기기 실행은 아니다.
- 이 환경의 `xcrun simctl`은 exit72로 실행되지 않았다. 연결된 실기기에서의 키보드·Safe Area·Android 뒤로가기·글꼴 렌더링·터치 검증은 수행하지 못했다.

최종 DOM 실측에서 목록 카드는 350×148, 소셜 버튼은 350×56, 소셜 레이블은 Pretendard 16/24였다. 브라우저 오류 로그는 없었고, 의존성 경로에서 `props.pointerEvents` 사용 중단 예정 경고 1건을 관찰했다.

독립 검토에서 코드상 추가 차단 결함은 발견되지 않았다. 최초 비교 캡처의 알림 꺼짐·설명 필드 초점은 시안의 기본 상태와 달랐으므로, 알림 켜짐·이름 필드 초점으로 계정·탈퇴·생성 캡처를 다시 촬영했다. 이는 토글/초점 상태 차이이며 해당 동작은 유지한다.

최종 독립 시각 검토: **APPROVE**, 추가 차단 항목 없음. 알림 켜짐·이름 초점으로 갱신한 세 캡처를 다시 확인했으며, 이 판정은 위 웹 비교 범위에 한정한다. 네이티브 실행 및 동일 해상도의 픽셀 diff를 대신하지 않는다.

## 입력창 재검증 및 수정

재검증에서 이전 육안 검토가 놓친 차이를 확인해 보완했다.

- Figma 생성 이름 입력(1702:19693)의 테두리는 브랜드색 1px이다. 웹에서는 같은 테두리에 브라우저 `outline: auto 1px`이 추가되어 두꺼워졌다. 공통 Field와 StudyField에 `outlineWidth: 0`, `outlineStyle: solid`를 적용했다. 너비만 0으로 설정하면 자동 포커스 링이 남는 것을 실제 화면에서 확인해 스타일도 명시했다.
- 생성 설명 도움말을 Figma의 “모이는 요일과 시간을 적어두면 초대할 때 설명이 줄어들어요”로 수정했다.
- 수정 후 생성 이름·설명, 프로필 이름, 쇼케이스 입력의 실제 DOM은 `border: 1px solid rgb(0,196,113)`, `outline: solid 0px`이었다. 키보드 포커스에서도 초록 테두리로 위치가 구분된다. 쇼케이스 저장 토스트 동작을 재확인했다.
- 생성·계정 최종 캡처를 갱신했다. 이번 판정도 동일 픽셀 diff나 실기기 검증을 의미하지 않는다.
- 최종 타입·Biome 검사 및 웹·iOS·Android 번들 export 통과. 수정된 생성·계정 캡처의 독립 시각 재검토도 APPROVE이며, 이번에 확인한 테두리·문구의 잔여 불일치는 발견되지 않았다.

## 이미지 마스크·해상도 정정

사용자 이미지 댓글을 기준으로 Figma 하위 마스크를 다시 검사했다. 이전 검토의 70px 사각 카드 이미지 판정은 잘못됐으며 아래 값으로 정정한다.

- 목록 마스크 그룹 `1702:19816`, 마스크 사각형 `1702:19817`: **64×64, 모서리 반경20px**, 별도 테두리 선 없음. 이미지 레이어 `1702:19818`의 소스는292×242다.
- 목록에 별도 `studyCard` 이미지를 사용하고64×64·반경20으로 표시한다. 초대 화면의70×70 이미지는 별도로 유지한다.
- Figma UI 이미지 다운로드 설정을3x로 변경해 원본 디자인에서 다시 내보냈다. 기존1x PNG를 로컬에서 단순 확대하지 않았다.

| 에셋 | PNG 픽셀 | 최대 표시 크기 | 배율 |
| --- | --- | --- | --- |
| 목록 썸네일 | 192×192 | 64×64 | 3x |
| 리마인더 | 156×147 | 52×49 | 3x |
| 로그인 토끼 | 354×354 | 118×118 | 3x |
| 초대 스터디 | 210×210 | 70×70 | 3x |
| 워드마크 | 600×300 | 200×100 | 3x |
| 빈 상태 | 450×450 | 150×150 | 3x |

일반 EntryIcon과 탭 아이콘은 SVG path이며 래스터 이미지가 아니다. 웹 DOM에서 목록·로그인·참여·빈 상태의 `naturalWidth/Height`와 표시 크기를 확인했다. 목록 썸네일 부모의 borderRadius20px도 확인했다. 새 목록·빈 상태 캡처를 저장했다. 물리적 고밀도 실기기 실행은 여전히 미검증이다.

이미지 수정 후 390px·622px 폭에서 웹 화면을 재확인했다. 622px에서도 썸네일 표시64×64·반경20px, 리마인더52×49가 유지된다. 타입·Biome 검사 및 웹·iOS·Android 번들 export를 통과했으며, 최신 목록 캡처와 자산·코드의 독립 검토도 APPROVE다.
