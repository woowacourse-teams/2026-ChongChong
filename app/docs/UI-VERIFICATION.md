# 이슈 #311 공통 UI 검증

기준일: 2026-09-14. 범위는 Expo 공통 기반과 쇼케이스다. 실제 로그인·스터디·공지·과제 기능 화면, API·인증·푸시·업로드·배포는 제외한다.

**현재 판정:** 보조 버튼과 탭 역할 유지 문제를 수정한 뒤 390px 웹 공통 UI 재검증을 통과했다. 최신 캡처9장·Figma 참조3장에 대한 독립 시각 검토와 코드 검토에서 추가 범위 내 불일치를 찾지 못했다. 아래 실패·불일치 서술은 수정 전 이력이며, 현재 결과는 마지막 「수정 후 반복 검증 결과」를 기준으로 한다. 네이티브 실행과 실질 린트 규칙 검증은 미완료다.

## 동작·정적 검증

- 전체 TypeScript 검사와 Biome22파일 포맷·구문 검사 통과. 현재 `rules.preset: "none"`으로 실제 린트 규칙은 꺼져 있어 린트 품질 검증 통과로 판정하지 않는다.
- 길이 초과 입력 → 빨간 오류 문구와 초록 포커스 테두리, 저장 비활성화 확인.
- 정상 입력 → 오류 해제, 초록 저장 버튼 활성화 확인.
- 저장 → 토스트 표시, 토스트 누르기 → 제거 확인.
- 후속 웹 재검증에서 모달 확인→안내 표시→닫기, 헤더 뒤로가기, 각 탭 이동·선택 상태는 작동했다. 그러나 스터디원 전환→스터디 홈 진입→공지 탭 클릭 시 리더로 초기화되는 문제를 CUA와 Playwright 클릭으로 각각 재현했다. 목 역할 유지에 대한 이전 성공 판정은 철회한다.
- 추가한 SVG의 잘못된 `accessible` DOM 속성과 이미지 resizeMode 경고를 수정했고, 새로고침 후 같은 동작에서 새 로그가 추가되지 않았다. 과거 개발 로그는 삭제하지 않았다.

최종 웹 캡처: `/tmp/chongchong-design-loop/common-top-final.jpg`, `common-bottom-final.jpg`. 모달·탭·오류 입력 캡처도 같은 디렉터리에 있으며 관련 소스 변경 당시의 검증 증거다.

## 보조 버튼 불일치 수정

위 후속 대조에서 발견한 보조 버튼을 수정했다. `secondary`는 흰 배경과 브랜드 글자를 사용하며 브랜드1px 테두리를 절대 배치로 안쪽에 그린다. 테두리를 레이아웃 높이에 더하지 않아 기존14px 상하 패딩과24px 글줄로52px을 유지한다. 비활성·로딩에서는 흰 글자·placeholder 배경을 유지하고 브랜드 테두리는 표시하지 않는다.

웹390×844 실측:350×52, 배경#FFFFFF, 글자·테두리#00C471, 테두리1, 반경12. 버튼 클릭→확인 모달 표시를 직접 확인했다. 캡처:`/tmp/chongchong-311-full-audit/web-secondary-fixed.jpg`. 타입 검사와 Biome 포맷·구문 검사22파일 통과. 이 항목의 이전 불일치 판정은 수정 후 일치로 갱신한다. 목 역할 유지·린트 규칙 비활성화 및 네이티브 실행 미검증은 별개로 남아 있다.

## 수정 후 반복 검증 결과

보조 버튼 수정 뒤 공통 UI와 탭 상태를 다시 검증했다. 탭의 RN Pressable이 링크 기본 탐색을 그대로 허용하던 문제는 Expo Router가 공개한 PlatformPressable로 교체했다. 의존성 추가 없이 공식 링크 처리를 복원했으며, 스터디원 전환→홈→공지→과제→멤버→홈→뒤로가기에서 역할이 유지됨을 직접 확인했다. 이전 역할 유지 실패 기록은 수정 전 재현 이력이며 현재 결과는 통과다.

수정 후 탭 실측은 버튼88×44·아이콘22×22·x52/140/228/316으로 기존 Figma 레이아웃을 유지한다. 버튼의 비활성/활성, 입력 오류/정상, 모달 취소/삭제 확인, 토스트 표시/닫기까지 다시 조작했다. 타입 검사와 Biome22파일 포맷·구문 검사는 통과했다. 신선한 웹 증거는 `/tmp/chongchong-311-loop-final`의 home/notices/assignments/members/showcase-top/error/toast-empty/confirm/delete 캡처다.

시안 판정의 범위는 이슈311의 웹 공통 컴포넌트와 내비게이션 골격이다. 실제 제품 화면의 내용·페이지 배치는 후속 이슈이며, Figma에 직접 대응하지 않는 쇼케이스 예시 문구와 로딩 시연은 제품 화면 일치 대상으로 보지 않는다. 네이티브 폰트·Safe Area·키보드·화면 읽기 검증과 실질 린트 규칙 활성화는 별도로 남아 있다.
