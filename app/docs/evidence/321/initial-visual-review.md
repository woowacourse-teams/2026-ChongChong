# #321 홈·알림 클론/시각 충실도 검토 (Pass B)

## 판정

**REQUEST_CHANGES**

실제 화면은 라이브 React Native 컴포넌트와 SVG로 구성되어 있고, 제공된 기하·타이포그래피 기준에서는 홈(멤버/리더)과 알림의 배치가 대체로 일치한다. 그러나 현 캡처는 유효한 PNG가 아니며, 멤버 화면은 마지막 `ActivityRow` 글꼴 변경보다 먼저 만들어져 현재 소스를 입증하지 못한다. 또한 변경한 화면의 치수와 여백이 토큰 대신 다수의 리터럴로 분산되어 있어 확장 가능한 디자인 시스템이라는 통과 기준을 충족하지 않는다.

## 확인한 증거

- 참조: `app/docs/evidence/321/figma-member.png`, `figma-leader.png`, `figma-notifications.png`
- 실제: `app/docs/evidence/321/member.png`, `leader.png`, `notifications.png`
- 구현: `app/src/app/study/index.tsx`, `app/src/features/home/ActivityRow.tsx`, `ActivityIcon.tsx`, `StudyHeader.tsx`, `app/src/app/notifications.tsx`, `app/src/ui/tokens.ts`, `app/src/ui/figmaVariables.ts`
- 명령 결과: `file` 및 `stat`으로 캡처 형식·생성 시각, 이미지 뷰어로 위 6개 화면을 직접 열어 비교.

## 좋은 점

- 홈 배너는 실재 `Image` 자산을 카드 내부에 배치하고, 제목·행·상태·탭은 모두 라이브 RN 뷰/텍스트/SVG로 렌더링한다. 화면 전체를 래스터 이미지나 `background-image`로 대체한 흔적은 없다. 배너 자산도 실제 RGBA PNG(360×360)다. `app/src/app/study/index.tsx:26`, `:38`, `app/src/features/home/ActivityIcon.tsx:10`.
- `ActivityRow`는 재사용 컴포넌트이며, 홈과 공지/과제 목록 모두에서 사용한다. 아이콘은 18×18, 녹색 1.8 stroke SVG라 기준과 맞는다. `ActivityRow.tsx:8`, `:35`, `ActivityIcon.tsx:10`, `:15-16`.
- 현재 소스 기준 멤버 행은 66 높이, 12 radius, 1px `rgba(15,23,42,.08)` border, 좌측 아이콘 시작 24 부근을 구현한다. `ActivityRow.tsx:46-57`, `figmaVariables.ts:4`.
- 현재 소스 기준 홈은 20px 좌우 여백의 350×120 배너, 64px 헤더, 120×120 일러스트를 구현한다. 리더 카드도 169px 폭과 106px 높이에 맞는 두 열 구조다. `StudyHeader.tsx:72-89`, `study/index.tsx:122-152`.
- 알림은 95px 행과 8px 간격으로 84/187/290 시작 위치를 만들며, 첫 알림은 36px 초록 원 안의 18px 흰 벨, 공지 알림은 배경 없는 18px 공지 SVG를 사용한다. 타이포그래피도 제목 16/24, 설명 13/18, 시간 12/18이다. `notifications.tsx:50-62`, `:79-104`, `tokens.ts:68-86`.
- 직접 본 실제 캡처에서 한국어 제목·설명·상태 텍스트는 모두 한 줄에 들어가며, 절단·겹침·잘못된 줄바꿈은 보이지 않았다. 메뉴·뒤로가기·공지·과제·벨 아이콘도 참조 화면의 의미와 구조에 맞다.

## 발견 사항

### HIGH

1. **[evidence] `.png` 증거 파일이 실제로는 JPEG이다.** `file app/docs/evidence/321/{figma-member,member,figma-notifications,notifications}.png`가 모두 `JPEG image data`를 반환했다. 이는 확장자와 파일 서명이 일치해야 한다는 캡처 검증 조건을 위반한다. 뷰어가 파일을 열 수 있더라도 캡처 파이프라인·알파 보존·후속 비교의 신뢰성을 보장할 수 없다. 올바른 PNG로 다시 캡처하고 각 파일의 시그니처와 390×763 실제 캡처 크기를 기록해야 한다.

2. **[evidence] 멤버 실제 캡처가 현 소스보다 오래됐다.** `member.png`는 02:14:14, `ActivityRow.tsx`는 제목을 14/20으로 고친 뒤인 02:14:40이다. 따라서 멤버 캡처는 현재 14px 제목 구현을 증명하지 못한다. 해당 화면을 현 소스에서 다시 캡처해야 한다. 리더(02:15:58)와 알림(02:14:58)은 각 관련 소스보다 새롭다.

3. **[product] 화면 핵심 토큰이 리터럴로 분산됐다.** 홈과 알림의 설계 치수가 토큰 계약으로 추출되지 않고 화면별 리터럴로 반복된다. 예: `ActivityRow.tsx:47-56`의 66/23/19/16/1/15, `study/index.tsx:126-154`의 20/32/120/16/6/12/106/14, `notifications.tsx:79-104`의 8/95/16/11/36/18/12/6/7. `tokens.ts`에는 해당 화면 전용 크기·여백·행·알림 토큰이 없다. 이는 새 홈 상태나 알림 변형으로 확장될 때 Figma 계약을 일관되게 유지할 수 없는 디자인 시스템 결함이다. 해당 값을 의미 있는 토큰으로 올리고 각 프리미티브가 그 토큰을 사용해야 한다.

### MEDIUM

1. **[evidence] 전체 캔버스와 실제 프레임의 범위가 다르다.** Figma 증거는 1249×675의 61% 축소된 편집기 전체(운영체제/편집기 영역 포함)이고, 실제는 OS 영역을 제외한 390×763이다. 따라서 픽셀 차이율·유사도 점수는 산정하지 않았다. 참조를 기기 프레임만 정확히 390×844로 내보내고, 실제도 같은 상태·영역으로 캡처한 뒤에만 픽셀 비교가 가능하다.

2. **[product] 홈의 실제 구성은 재사용 행과 화면별 카드의 혼합이다.** 행은 재사용되지만, 배너·통계 카드는 `study/index.tsx` 내부 스타일에 남아 있어 홈 변형 간 primitive 레벨의 재사용이 제한된다. 현 시각 캡처에는 결함으로 드러나지 않았지만, 위 토큰화와 함께 Banner/StatCard를 프리미티브화해야 같은 구조를 유지할 수 있다. `study/index.tsx:27-48`, `:50-85`, `:130-154`.

### LOW

없음.

## 남은 미검증

- 동일 프레임·동일 OS 안전영역으로 정규화된 참조가 없으므로 픽셀 diff, 알파 채널, 정확한 색상 차이는 판정하지 못했다.
- 현 캡처는 정지 상태만 제공한다. 메뉴 열림, 누름, 읽음 처리 뒤 화면은 이번 Pass B 범위에서 검증하지 않았다.
