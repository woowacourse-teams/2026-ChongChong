# 공지 #323 Pass A 재검토

판정: PASS (UI 로컬 시나리오 범위의 정적 무결성)
검토 시점: 2026-09-15. 이전 REVISE 이후 최신 변경 소스를 다시 읽었다. 코드 변경, 브라우저, 실기기 실행은 하지 않았다. 아래 실행 결과는 root가 전달한 검증이며 이 검토자가 직접 재현한 결과가 아니다.

## 이전 지적 해결

- edit.tsx:38-42 이미지 및 리마인드를 JSON 값으로 비교한다. 새 글 이미지 단독 추가, 기존 리마인드 삭제, 같은 개수의 리마인드 교체가 dirty에 포함된다.
- edit.tsx:43-50 usePreventRemove가 navigation 제거를 차단하고 pending action을 확인 모달에 보존한다. 취소는 편집 유지, 확인은 원래 action 재실행이다. 저장 성공의 allowLeave와 dismissTo가 저장 후 불필요한 이탈 확인 및 기존 상세 중복을 피한다. 실제 네이티브 제스처 동작은 미실행이다.
- studies.tsx:61 getNotices(study.id).length를 StudyCard에 공급하여 생성/삭제와 초기 fixture 수가 동기화된다.
- NoticeCard.tsx:28-42 예약 배열의 다음 시각으로 분/시간/일 안내를 계산한다. 고정된 2026-08-05 17:59 미리보기 시계를 사용하는 UI 시나리오 조건에서 이전의 모든 예약 '1분 뒤' 표시는 해결됐다. 실제 시계 기반 예약 실행은 구현/검증 범위가 아니다.
- NoticeReader.tsx:51-52,81-89 본문 레이아웃 폭으로 단일 이미지 크기를 계산한다. 350:375 비율을 유지한다. root가 320px 화면에서 280×300을 실측했다고 전달했다.
- '이미지 끝' 조건은 root가 Figma 요구를 세로 본문 끝 도달로 확정했다. 따라서 가로 첨부 마지막 이미지 스크롤을 요구했던 이전 확인 항목은 결함에서 제외한다. member/self/unread 조건과 세로 끝 조건이 유지된다.

## 추가 변경 확인

- ActivityProvider.tsx:45-52 알림의 공지가 해당 스터디에 실제 존재할 때만 표시하여 삭제된 공지 알림 및 unread count를 제거한다.
- notices/[id].tsx:142 삭제 후 목록 dismissTo를 사용한다.
- ReminderSheet.tsx:150-159 시간 목록 생성 완료 시 34×40+8 위치로 이동하여 17:00부터 시작한다.
- provider의 스터디별 상태, leader 쓰기 제한, member/self 읽음 제한, 로컬 이미지 URI 저장 경계는 유지된다.
- 공통 AppText/ConfirmDialog/Header/tokens와 독립 컴포넌트를 사용하며 화면 전체 스크린샷을 구현으로 대신하지 않았다.

## 검증 한계와 문서 반영 항목

- root 전달: 웹에서 리마인드 삭제 후 뒤로가기 확인/취소, 320px 단일 이미지 크기를 확인했다. 이 검토자는 CUA를 사용하지 않았으므로 시각 PASS 자체는 root 결과에 따로 의존한다.
- Android 시스템 뒤로가기, iOS 스와이프, OS 이미지 선택기 및 글자 확대/Safe Area는 실제 실행 미확인이다.
- 검토 시점 app/docs/NOTICE_UI.md는 아직 없었다. 최종 문서에 고정 미리보기 시계, 세로 끝 읽음 기준, 네이티브 미실행을 명시해야 한다.
- DESIGN.md 공지 본문은 14/24라고 적혀 있으나 최신 NoticeReader는 large(16)/24를 사용한다. Figma 재확인 결과에 맞게 최종 문서 수치를 동기화할 항목이다.

남은 확실한 기능 결함은 이번 재검토에서 발견하지 못했다.
