# 스터디 생성·참여·홈

[← 현재 PRD](README.md) · [구현 범위](scope.md)

## 사용자 흐름

1. 내 스터디 목록에서 기존 스터디를 선택하거나 이름·설명을 입력해 새로 만든다.
2. 생성자는 리더가 된다. 초대 링크로 참여한 사용자는 일반 멤버가 된다.
3. 리더는 홈에서 최초 작성 후 7일 미만인 미확인 공지와 아직 완료되지 않은 과제, 각각 완료한 인원을 확인한다. 일반 멤버는 자신이 아직 읽지 않은 공지와 제출하지 않은 과제를 확인한다.
4. 스터디 내부에서 공지·과제·멤버·관리 화면으로 이동한다.

## 입력과 참여 제한

| 항목 | 현재 정책 |
| --- | --- |
| 스터디 이름 | 필수, 공백만 입력 불가, 최대 15자 |
| 설명 | 선택, 최대 30자 |
| 사용자별 소속 수 | 생성·참여 합계 최대 50개 |
| 스터디 인원 | 리더 포함 최대 50명 |
| 초대 링크 | 소속 멤버가 조회 가능, 토큰 발급 시점부터 3일 유효 |
| 중복 참여 | 거부 |

초대 링크가 만료되었거나 올바르지 않으면 참여할 수 없다.
서버는 초대 토큰을 확인하고, 스터디가 존재하는지, 이미 참여한 사용자인지, 인원 제한을 넘는지 확인한다.
새로 가입한 멤버도 이전 공지와 과제를 읽을 수 있다. 다만 이전 공지의 확인 대상이나 과제의 제출 대상이 자동으로 되지는 않는다. 과제는 리더가 제출 대상 변경 API로 나중에 추가할 수 있다(#638 서버·#653 웹 병합 기준).

## 공개 탐색과 참여 전 정보

서버 생성 API는 `isPublic`을 필수로 받는다. 공개 스터디는 인증된 사용자가 이름 검색·최신순 커서 조회를 할 수 있으며, 정원 50명이 찬 스터디는 탐색 목록에서 제외한다. 가입한 스터디도 목록에서 제외하지 않는다.
공개 스터디는 `studyId`만으로 참여 전 정보를 조회하거나 참여할 수 있다. 비공개 스터디는 유효한 초대 토큰이 필요하다. 토큰을 보내면 공개 여부와 관계없이 검증하며, `studyId`도 보내면 토큰의 스터디와 일치해야 한다.
현재 웹 생성 요청은 `isPublic: false`를 전송한다. 공개 탐색 API와 웹 연결 여부를 혼동하지 않는다.

스터디 대표 이미지는 업로드 완료된 본인 소유·미연결 `imageFileId`로 설정한다. 서버 기본 정책은 JPEG·PNG·WebP, 0바이트 초과·최대 5MiB다. 웹 생성·수정 폼에서 이미지를 설정하며, 초기화 규칙은 [스터디 관리](settings.md)를 따른다.

## 월간 일정 조회

서버는 `GET /api/studies/{studyId}/calendar?year=2026&month=11`로 현재 멤버의 월간 일정을 제공한다. 공개 스터디도 비멤버에게 일정을 공개하지 않는다.

- 공지는 가입 전·후와 확인 대상 여부에 관계없이 모두 포함한다.
- 과제는 현재 본인이 제출 대상으로 지정된 것만 포함하며 리더에게도 같은 조건을 적용한다. 대상에서 제외하면 보존된 제출물이 있어도 일정에서 빠지고 재지정하면 다시 포함한다.
- 공지 생성·과제 생성·과제 마감은 각각 별도 이벤트다. 한국 시간 월 시작은 포함하고 다음 달 시작은 제외하며, 생성 월과 마감 월이 다르면 각각 해당 월에 표시한다.
- 완료된 항목도 반환한다. 읽음·제출 상태는 조회 시점의 본인 상태이며 과거 상태나 전체 집계가 아니다.
- 제목·마감일 변경과 삭제는 현재 원본을 반영한다. 과거 이력이나 별도 기타 일정은 저장하지 않는다.
- 월간 이벤트를 페이지 제한 없이 시각·이벤트 종류·원본 ID 순으로 반환한다. 일정이 없으면 빈 배열이다.

웹은 월간 API의 일정을 날짜별로 표시하고 공지·과제 상세 화면으로 연결한다(#652). 응답의 읽음·제출 상태는 검증하지만 일정 항목에는 별도로 표시하지 않는다. 실제 브라우저와 배포 환경의 동작은 이번 작업에서 확인하지 않았다.
근거: [캘린더 서비스](../../../backend/src/main/java/withoutc/chongchong/study/service/StudyCalendarService.java), [월간 API 계약](../../../backend/docs/openapi/paths/studies/calendar.yaml).

## 목록과 홈에 표시하는 정보

내 스터디 목록에는 최근에 참여한 스터디부터 표시한다. 각 스터디의 인원과 남은 공지·과제 수도 함께 보여준다.
리더에게는 대상 멤버가 모두 완료했는지를 기준으로 남은 활동 수를 보여준다. 공지는 최초 작성 후 7일 미만인 항목만 세며, 정확히 7일이 지나면 미확인 멤버가 남아 있어도 홈 요약과 목록의 공지 개수에서 제외한다(#654 백엔드 구현 기준). 일반 멤버에게는 본인이 해야 하는 활동 중 아직 완료하지 않은 수를 보여준다.
과제는 마감 전에 제출했든 늦게 제출했든 완료한 것으로 센다. 공지의 기간 기준과 전체 목록 보존 정책은 [공지](notice.md#리더-화면에-표시하는-기간)를 따른다.

리더 홈에서 스터디 인원이 한 명이면 멤버 초대 배너를 표시하고 멤버 화면으로 안내한다.
