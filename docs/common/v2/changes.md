> [!IMPORTANT]
> 프론트엔드와 백엔드가 함께 맞출 계약은 공개 범위, 활동 대상 상태, 첨부 정보, 리더 양도 후 역할, 알림 상태다.
> 구체적인 미정 정책은 아래 항목과 각 기능 문서에서 확인한다.

## 구현 범위를 먼저 확정할 항목

- **허용 제출 형식 선택:** 메모에는 있지만 작성 화면의 명시적 선택 UI는 확인되지 않았다. 파일 첨부 기능과 별도로 결정한다.
- **읽음 처리:** 자동 완료 안내와 읽음 버튼 표현이 혼재한다. 현재 v1 자동 처리와 최종 UX를 대조한다.
- **마감 후 제출:** v1은 허용하며 v2 차단 요구는 확인되지 않았다.
- **방출 후 재가입:** v2 안내 문구가 영구 재가입 차단을 의미하는지 확인한다.
- **알림 확대:** 읽음·제출 직후 리더 알림은 피드백 이후 검토 항목으로 남긴다.

각 기능의 미정 값과 화면 문구 불일치는 [확인할 정책](scope.md)을 참고한다.

## 작업 의존 관계

- 업로드 기반 → 공지·과제·제출물 첨부 연결 → 공개 정책에 맞는 첨부 조회.
- 조회·할당·리더 참여·공개 정책 → 역할별 화면·홈 집계 → 리마인드 대상 선정.
- 계정·기기 수신 설정 → 실제 푸시 발송 → 알림 목록·읽음 동작 연결.
- 리더 양도 정책 → 양도 API·화면 → 리더 회원탈퇴 제한과 연계.

> [!NOTE]
> 기존 생성·조회·수정·삭제를 모두 새로 구현하는 작업은 아니다.
> v1 동작을 유지하면서 위 차이를 반영하며, 미정 정책은 디자인 예시만으로 확정하지 않는다.
