`frontend/src/features`의 화면·요청 코드와 `backend/src/main/java/withoutc/chongchong`의 서비스·정책·모델을 대조했다.
각 기능 문서의 근거 링크는 실제 구현 파일을 가리킨다.

## 사용할 수 있는 기능

| 범위 | 기능 |
| --- | --- |
| 웹·서버 연결 | 카카오 로그인과 다중 세션, 스터디 생성·참여·수정·삭제, 멤버 목록·방출·탈퇴 |
| 웹·서버 연결 | 공지 자동 읽음, 과제 제출·수정·공개 설정·리더 참여·5개 상태 표시 |
| 웹·서버 연결 | 계정 이름 수정, 소속 스터디 이름 동기화, 계정 탈퇴, 알림함, Web Push 구독·최초 클릭 기록 |
| 서버만 제공 | 공지·과제의 예약 리마인드 등록·변경·발송, S3 업로드 URL 발급 |
| 현재 구현 없음 | Google·Apple 로그인, 리더 양도, 스터디별 독립 이름 수정, 업로드 완료 확인·게시물 첨부 연결·웹 첨부 화면 |

웹과 서버의 입력·응답 제약도 일부 다르다. 웹에서는 과제의 제출 방법과 제출 내용을 필수로 받지만 서버는 선택 값으로 받는다.
제출 상세 API의 `createdAt·content=null` 응답은 웹 검증이 거부한다. [과제](assignment.md)에 현재 제약을 정리했다.

모바일 홈 화면에 설치해 사용하는 기능과 브라우저 푸시는 웹에서 제공한다. 삭제한 네이티브 시연용 패키지는 이 문서의 기능 범위에 포함하지 않는다.

어떤 행동을 할 수 있는지는 역할뿐 아니라 스터디에 소속되어 있는지, 확인·제출 대상인지, 제출물이 공개되어 있는지에 따라 달라진다.
서버에서도 이 조건을 확인하므로, 화면에 버튼을 숨기는 것만으로 권한을 제한하지 않는다.

## 동작을 확인할 때 사용할 시나리오

아래 표는 기능을 확인할 때 기대하는 결과다. 이번 문서 작업에서 실제로 실행한 테스트 결과는 아니다.

| 조건과 행동 | 기대 결과 |
| --- | --- |
| 로그인 후 스터디 생성 | 생성자가 리더가 되고 내 목록에 표시 |
| 서로 다른 브라우저에서 로그인 후 한쪽 갱신·로그아웃 | 다른 브라우저의 세션 유지 |
| 발급 후 3일이 지난 초대 링크로 참여 | 참여 거부 |
| 이미 50개 스터디에 소속되거나 대상 스터디가 50명인 상태에서 참여 | 제한 오류 |
| 공지·과제 작성 뒤 새 멤버 가입 | 이전 글 열람 가능, 확인·제출 대상에는 추가되지 않음 |
| 확인 대상 멤버가 공지 끝까지 읽기 | 자동 읽음 요청과 완료 상태 표시 |
| 과제 마감 뒤 처음 제출 | 지각 제출, 리더 완료 인원에 포함 |
| 비공개 과제에서 타인 제출물 조회 | 일반 멤버 접근 거부 |
| 계정 이름 수정 | 모든 소속 스터디의 멤버 이름에 반영 |
| 리더가 스터디 탈퇴 또는 회원탈퇴 | 서버에서 거부 |
| 알림함 항목 선택 | 읽음 처리 요청 및 관련 화면 이동 |
| 브라우저 푸시 클릭 | 서명 토큰으로 최초 클릭 기록 요청과 관련 화면 열기를 각각 시도 |
| 인증 후 파일 업로드 URL 발급 | 파일 ID·PUT URL·만료 시각 반환. 실제 업로드 완료나 게시물 첨부는 보장하지 않음 |

## 확인한 내용과 아직 확인하지 않은 내용

이번 갱신은 현재 웹·서버 코드와 API 계약을 대조한 문서 작업이다. 과거의 독립 시연 패키지 제거는 이번 변경에 포함하지 않는다.
백엔드 테스트는 882개 통과했고 Docker 미실행으로 PostgreSQL 기반 55개가 건너뛰어졌다. 이에 따라 알림·Web Push API 6개의 성공 호출 기록이 없어 전체 API 커버리지 검사는 실패했다. 전체 검증 통과로 보지 않는다.
실제 카카오 로그인, 기기 간 로그인 유지, 운영 푸시 수신, S3 업로드와 배포 상태는 별도 확인이 필요하다.
