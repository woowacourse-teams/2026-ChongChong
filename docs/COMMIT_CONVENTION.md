# 커밋 컨벤션

## 기본 형식

커밋 메시지는 아래 형식을 사용합니다.

```text
<type>: <summary>
```

- `type`은 영문 소문자로 작성합니다.
- `summary`는 변경 내용을 간결한 한국어로 작성하고 마침표를 붙이지 않습니다.
- 하나의 커밋에는 함께 되돌려야 하는 하나의 논리적 변경만 포함합니다.

예시:

```text
feat: 모임 생성 기능 추가
fix: 로그인 만료 시 리다이렉트 오류 수정
docs: 브랜치 전략 문서화
chore: CodeRabbit 리뷰 설정 추가
```

## 타입

| 타입       | 사용 시점                                               |
| ---------- | ------------------------------------------------------- |
| `feat`     | 새로운 기능을 추가할 때                                 |
| `fix`      | 버그를 수정할 때                                        |
| `refactor` | 동작 변경 없이 코드 구조를 개선할 때                    |
| `test`     | 테스트를 추가하거나 수정할 때                           |
| `docs`     | 문서만 추가하거나 수정할 때                             |
| `style`    | 포매팅 등 코드 동작에 영향을 주지 않는 표현을 수정할 때 |
| `perf`     | 성능을 개선할 때                                        |
| `build`    | 빌드 도구나 의존성을 변경할 때                          |
| `ci`       | CI/CD 설정을 변경할 때                                  |
| `chore`    | 위 타입에 속하지 않는 설정이나 유지보수 작업을 할 때    |
| `revert`   | 이전 커밋을 되돌릴 때                                   |

## 본문과 이슈 연결

변경 이유나 의사결정이 제목만으로 충분하지 않다면 빈 줄 다음에 본문을 작성합니다. 이슈 연결이 필요하면 마지막에 `Refs #<이슈번호>`를 추가합니다.

```text
refactor: 인증 예외 처리 책임 분리

컨트롤러마다 중복되던 인증 예외 변환을 전역 예외 처리기로 이동한다.

Refs #12
```

## PR 제목과의 차이

커밋 메시지와 PR 제목은 서로 다른 형식을 사용합니다.

| 구분 | 형식                 | 예시                                |
| ---- | -------------------- | ----------------------------------- |
| 커밋 | `<type>: <summary>`  | `chore: CodeRabbit 리뷰 설정 추가`  |
| PR   | `[<type>] <summary>` | `[chore] CodeRabbit 리뷰 설정 추가` |

작업 브랜치는 `dev`에 Squash merge하므로 PR 제목이 `dev`에 남는 최종 커밋 제목이 됩니다. PR 제목의 타입과 내용도 실제 변경 범위를 대표해야 합니다.
