# 0050. 서명된 단기 토큰으로 푸시 클릭 기록을 인증한다

- 날짜: 2026-10-13
- 관련 이슈: [#495](https://github.com/woowacourse-teams/2026-ChongChong/issues/495)
- 대체하는 ADR: [0049](0049-record-push-clicks-on-deliveries.md)의 클릭 API 인증 방식

## 배경

서비스 워커의 `notificationclick` 이벤트는 브라우저 알림을 눌렀을 때 발생하며, 앱 세션이 만료됐거나 로그인 화면으로 이동한 상태에서도 클릭 시각을 기록해야 한다. 기존 인증 API만 사용하면 클릭 시점에 세션이 없을 때 로그인 복구 전까지 클릭 기록이 누락되거나 deepLink 이동 흐름이 복잡해진다.

로그인 없이 클릭 API를 열면 누구나 발송 내역 ID를 추측해 클릭 시각을 기록할 수 있다. 발송 내역 ID만으로 요청을 허용하지 않고, 푸시를 보낸 백엔드가 발급한 검증 가능한 자격 증명이 필요하다.

## 결정

푸시 payload에 `deliveryId`와 서명된 `clickToken`을 포함한다. `POST /api/notification-deliveries/{deliveryId}/click`은 로그인 인증 없이 호출할 수 있고, body의 `clickToken`을 검증한 뒤 클릭 시각을 기록한다.

토큰은 `HMAC-SHA-256`으로 서명한다. 서명 원문은 버전 접두사 `push-click-v1`, 경로의 `deliveryId`, 만료 시각(epoch second)으로 구성한다. 토큰 바이트는 32바이트 서명과 8바이트 만료 시각을 이어 붙인 뒤 padding 없는 URL-safe Base64로 인코딩한다. 토큰은 발급 후 7일이 지나면 만료한다. delivery ID 자체는 토큰 바이트에 중복 저장하지 않으며, 검증할 때 경로의 ID로 서명을 재계산해 같은 전달 건에만 사용할 수 있게 한다.

서명 비밀 키는 `WEB_PUSH_NOTIFICATION_CLICK_TOKEN_SECRET` 환경 변수에서 Base64로 읽는다. 최소 32바이트 키를 사용한다. 같은 환경의 모든 백엔드 인스턴스는 동일한 키를 사용해야 하며, 로컬·dev·prod 환경 간 키를 공유할 필요는 없다.

클릭 API는 요청 시각을 저장하고, 순차 반복 요청은 최초 `clicked_at`을 유지한다. 유효하지 않거나 만료된 토큰은 `INVALID_CLICK_TOKEN`으로 거부한다. 이 API는 클릭 시각 기록만 수행하므로 유효한 토큰 재사용은 최초 시각을 바꾸지 않는다.

## 선택 이유

토큰이 발송 내역 ID와 만료 시각에 묶여 있어 로그인 세션 없이도 요청의 출처와 범위를 검증할 수 있다. ID만 전달하는 방식보다 무단 기록을 막고, 사용자별로 다른 인증 흐름을 구현하는 것보다 서비스 워커와 앱의 세션 상태에 덜 의존한다.

## 검토한 대안

### 클릭 API에 로그인을 요구한다

로그인 세션이 유효한 경우 구현이 단순하지만, 앱이 백그라운드에서 열린 뒤 세션 복구가 필요한 상황에서 클릭 기록이 지연되거나 누락될 수 있으므로 선택하지 않았다.

### deliveryId만으로 클릭 API를 공개한다

인증 절차는 가장 단순하지만 식별자를 아는 누구나 클릭 시각을 조작할 수 있으므로 선택하지 않았다.

## 영향

### 긍정적 영향

- 로그인 세션이 없어도 푸시 클릭을 기록할 수 있다.
- 토큰을 다른 `deliveryId`에 사용할 수 없고 만료 후에는 재사용할 수 없다.
- `clicked_at`의 최초 시각 유지 규칙으로 같은 토큰의 반복 요청은 멱등하게 동작한다.

### 부정적 영향과 위험

- 환경별 비밀 키 설정과 같은 환경 내 인스턴스 간 키 일치가 필요하다.
- 토큰이 만료된 뒤 클릭 API를 처음 호출하면 클릭을 기록하지 못한다.
- 토큰을 탈취한 주체는 만료 전까지 해당 전달 건의 클릭을 앞당겨 기록할 수 있다.
- 비밀 키를 교체하면 이전 키로 발급한 토큰은 모두 무효화된다.

## 미확정 사항

- 비밀 키 교체 시 기존 토큰을 유예할 다중 키 검증이 필요한지 여부

## 후속 작업

- 프론트 서비스 워커가 `deliveryId`와 `clickToken`을 앱에 전달하고, 세션 없이 클릭 API를 호출하도록 연동한다.
- 배포 환경에 `WEB_PUSH_NOTIFICATION_CLICK_TOKEN_SECRET`을 설정한다.
