# 0046. 사용자 이름 수정 제한을 소셜 프로필 초기화 제한과 구분한다

- 날짜: 2026-10-03
- 관련 이슈: [#423](https://github.com/woowacourse-teams/2026-ChongChong/issues/423)
- 관련 ADR: [0009. 제공자 독립 소셜 로그인 경계를 구성한다](0009-establish-provider-independent-social-login-boundary.md),
  [0025. 모든 생성 경로에서 성립할 불변식은 도메인 모델이 보호한다](0025-own-stable-invariants-in-domain-model.md)
- 일부 대체 관계: ADR 0025의 "변경 가능한 필드는 최초 생성과 변경 메서드에 같은 규칙을 적용한다"는 원칙 중 `User.name`의 길이 제한

## 배경

소셜 최초 로그인은 공급자의 표시 이름으로 `User`를 생성한다. 현재 `User.name`은 공백이 아닌 최대 255자를 허용하고,
재로그인 시 기존 이름을 공급자 값으로 덮어쓰지 않는다. 반면 홈 마이페이지 디자인은 사용자가 직접 입력하는 이름을
8자 이하로 안내한다. 저장 가능한 이름 전체를 8자로 줄이면 기존 계정과 공급자 이름의 생성·재로그인 경로가 영향을 받는다.

ADR 0025는 변경 가능한 필드의 생성과 변경에 같은 검증 규칙을 적용하도록 정했다. 이번 이름 수정 API는 소셜 프로필
초기화와 사용자의 직접 입력이 서로 다른 목적을 가지므로, 그 길이 규칙에 한정된 예외를 명시해야 한다.

## 결정

- `User.name`의 공통 불변식은 `null` 또는 공백만 있는 값 금지와 저장 가능한 최대 255자다. 소셜 최초 로그인으로
  사용자를 생성할 때 이 규칙을 유지한다.
- 사용자가 `PATCH /users/me`로 직접 이름을 수정할 때는 공통 불변식에 더해 최대 8자를 적용한다. 이름 누락,
  `null`, 빈 문자열, 공백만 있는 문자열, 8자 초과는 `INVALID_USER_NAME`으로 거부한다.
- 이 추가 제한은 사용자 이름 변경 경로에서 검증한다. 요청 DTO만 검증하고 도메인 변경 메서드를 우회해 8자 초과
  이름으로 수정할 수 있게 두지 않는다. JSON 형식 오류는 기존 `INVALID_REQUEST` 계약을 따른다.
- 기존에 저장된 9~255자 이름은 조회와 재로그인만으로 변경하거나 무효화하지 않는다. 사용자가 이름을 수정할 때는
  새 이름에 8자 제한을 적용한다.

이번 결정은 이름 길이 정책에 한정된다. 홈 이름 수정 시 현재 참여 중인 스터디 멤버의 이름을 동기화하는 정책은
[ADR 0047](0047-sync-home-name-to-current-study-memberships.md)을 따른다.

## 선택 이유

저장 모델의 255자 허용 범위와 사용자가 직접 입력하는 8자 제한을 분리하면 기존 소셜 계정의 값을 보존하면서
마이페이지 입력 정책을 적용할 수 있다. 변경 메서드에서도 8자 제한을 확인하면 Controller 외의 호출 경로에서도
같은 사용자 수정 정책이 유지된다.

## 검토한 대안

### 생성과 변경 모두 8자로 제한한다

하나의 검증 메서드를 유지할 수 있지만, 공급자가 보낸 긴 표시 이름과 기존 계정 데이터를 처리하는 정책까지
변경해야 한다. 이번 이름 수정 범위를 넘어가므로 채택하지 않는다.

### 수정 API도 255자까지 허용하고 화면에서만 8자로 제한한다

서버 검증 규칙은 단순해지지만 다른 클라이언트가 디자인에서 허용하지 않는 길이로 홈 이름을 수정할 수 있다.
API가 사용자 수정 정책을 보장하도록 서버에서도 제한한다.

## 영향

### 긍정적 영향

- 기존 소셜 프로필 이름과 계정 데이터를 유지한다.
- 홈 마이페이지의 이름 입력 제한을 서버에서도 일관되게 적용한다.

### 부정적 영향과 위험

- `User`의 생성과 이름 변경에 서로 다른 최대 길이 규칙이 생긴다.
- 기존 이름이 8자를 넘는 사용자는 그대로 조회할 수 있지만, 이후 직접 수정하려면 8자 이하의 이름을 입력해야 한다.

## 미확정 사항

없음.

## 후속 작업

- 사용자 이름 변경 메서드와 `PATCH /users/me`에서 이 정책을 구현한다.
- 8자 경계값, 9자 초과, 누락·공백 이름 및 기존 긴 이름 보존을 테스트한다.
