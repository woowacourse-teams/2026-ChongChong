# 0047. 홈 이름 변경을 현재 참여 스터디의 멤버 이름에 동기화한다

- 날짜: 2026-10-06
- 관련 이슈: [#455](https://github.com/woowacourse-teams/2026-ChongChong/issues/455),
  [#423](https://github.com/woowacourse-teams/2026-ChongChong/issues/423)
- 관련 ADR: [0029. 스터디 멤버십 상한을 행 잠금과 트랜잭션으로 보호한다](0029-protect-study-membership-limits-with-row-locks.md),
  [0046. 사용자 이름 수정 제한을 소셜 프로필 초기화 제한과 구분한다](0046-separate-user-name-edit-limit-from-social-initialization.md)
- 변경하는 계약: #423의 `PATCH /api/users/me` 명세 중 기존 스터디 멤버 이름을 변경하지 않던 정책

## 배경

홈 프로필 이름은 `User.name`에, 스터디에 표시하는 멤버 이름은 `StudyMember.name`에 각각 저장한다.
스터디 생성·가입 시점에는 현재 홈 이름을 복사하지만, #423에서 구현한 홈 이름 수정은 `User.name`만 변경한다.
따라서 이름을 수정한 뒤에도 기존에 참여 중인 스터디에는 이전 이름이 표시된다.

현재 스터디별 프로필 조회·수정 기능은 구현되지 않았다. 이 단계에서 기존 스터디의 이름을 별도로 유지할 사용자 경로도
없으므로, 홈 이름을 바꿨을 때 기존 참여 스터디에도 새 이름이 표시되도록 할 필요가 있다.

## 결정

- `PATCH /api/users/me`로 홈 이름을 수정하면 같은 사용자의 현재 `StudyMember` 행 모두에서 `name`을 새 홈 이름으로
  변경한다. 리더와 일반 멤버를 구분하지 않는다.
- `User.name`과 해당 `StudyMember.name` 변경을 하나의 트랜잭션에서 처리한다. 중간에 실패하면 함께 롤백한다.
- 스터디 생성·가입과 이름 수정이 동시에 일어날 때 서로 다른 이름이 저장되지 않도록, 이름 수정도 기존 생성·가입 경로와
  동일하게 먼저 해당 `User` 행을 쓰기 잠금으로 조회한 뒤 이름과 멤버십을 변경한다.
- 새 스터디를 생성하거나 가입할 때 현재 홈 이름을 멤버 이름의 초깃값으로 복사하는 기존 동작은 유지한다.
- 이번 결정은 이름에만 적용한다. 홈 프로필 이미지 또는 기존 스터디 멤버의 프로필 이미지는 변경하지 않는다.
  요청·응답 형식과 이름 검증 규칙도 유지한다.
- 과거에 이미 저장된 서로 다른 이름을 일괄 보정하지 않는다. 이후 해당 사용자가 홈 이름을 수정할 때 현재 참여 중인
  멤버십을 동기화한다.

## 선택 이유

현재 제공하는 프로필 수정 경로는 홈 이름 수정뿐이다. 따라서 기존 스터디의 이름을 그대로 두는 것보다 현재 참여
스터디에 변경된 이름을 반영하는 편이 사용자가 기대하는 표시와 일치한다. 이미 저장된 멤버십 이름을 갱신하면 스터디
멤버 목록 등 기존 조회 경로도 별도 조회 규칙 변경 없이 새 이름을 반환한다.

스터디 생성·가입은 사용자 행을 먼저 잠근 다음 그 사용자의 현재 이름을 복사한다. 이름 수정도 같은 사용자 행을 잠그면
동일 사용자의 생성·가입과 수정이 직렬화되어, 각 멤버십이 갱신 전후 중 한 시점의 이름을 일관되게 저장한다.

## 검토한 대안

### 홈 이름만 변경하고 기존 멤버십은 유지한다

스터디별 이름을 독립적으로 둘 여지는 있지만, 현재는 스터디별 프로필을 조회·수정하는 기능이 없다. 사용자는 홈 이름을
바꿔도 기존 스터디에서 이전 이름을 보게 되므로 이번 단계에는 적합하지 않다.

### 스터디 조회 시마다 사용자 이름을 참조한다

저장된 이름을 갱신하지 않아도 되지만, 스터디 멤버 이름을 사용하는 모든 조회 경로를 바꿔야 한다. 또한 현재 저장된
`StudyMember.name`과 조회 결과의 의미가 달라지므로 채택하지 않는다.

### 이름 수정 후 비동기적으로 멤버십을 갱신한다

수정 응답 이후 한동안 홈과 스터디에 다른 이름이 표시될 수 있고, 실패 시 재시도와 복구 전략이 필요하다. 사용자당
현재 멤버십 상한이 50개이므로 이번 범위에서는 단일 트랜잭션 갱신을 선택한다.

## 영향

### 긍정적 영향

- 홈에서 이름을 수정하면 현재 참여 중인 모든 스터디에서도 같은 이름이 표시된다.
- 홈 이름과 스터디 멤버 이름이 일부만 변경되는 상태를 방지한다.
- 기존 API의 요청·응답 형식과 스터디 조회 경로를 유지한다.

### 부정적 영향과 위험

- 이름 수정 시 참여 중인 멤버십을 모두 갱신하므로 쓰기 작업과 트랜잭션 시간이 늘어난다.
- 같은 사용자에 대한 스터디 생성·가입은 사용자 행 잠금이 끝날 때까지 대기할 수 있다.
- 향후 스터디별 이름 수정 기능을 도입하면 현재의 일괄 동기화 정책과 충돌할 수 있다.

## 미확정 사항

- 스터디별 프로필을 별도로 제공할지, 제공한다면 홈 이름 변경 후 스터디별로 수정한 이름을 유지할지 여부는
  해당 기능을 설계할 때 결정한다. 이번 ADR은 현재 구현 단계의 동기화 정책만 정한다.

## 후속 작업

- `PATCH /api/users/me`의 OpenAPI 설명을 현재 동기화 정책으로 변경한다.
- 사용자 이름 수정 경로에서 사용자 행 잠금과 모든 현재 멤버십의 이름 갱신을 구현한다.
- 여러 스터디 참여, 리더·일반 멤버, 다른 사용자 및 이미지 불변, 실패 시 롤백, 생성·가입과의 동시성을 검증한다.
