# 0048. 스터디 초대 토큰에 3일 만료를 적용한다

- 날짜: 2026-10-07
- 관련 이슈: [#466](https://github.com/woowacourse-teams/2026-ChongChong/issues/466)
- 관련 ADR: [0039. 고정 길이 키 기반 스터디 초대 토큰을 사용한다](0039-use-fixed-length-keyed-study-invite-tokens.md)
- 일부 대체 관계: ADR 0039의 22자 고정 길이, 같은 스터디의 안정 토큰 생성, 무기한 유효 정책을 대체한다.

## 배경

초대 토큰에 만료 시각이 없어 링크를 발급한 뒤에도 계속 사용할 수 있었다. 스터디에서 방출된 멤버가 기존 초대 코드를
가지고 있으면 다시 가입할 수 있고, 해당 코드가 바뀌지 않는 한 이 동작이 반복된다. 기존 토큰의 유효 기간을 제한해
오래된 초대 코드의 재사용 가능 기간을 줄일 필요가 있다.

## 결정

- 초대 토큰은 발급 시각부터 3일 동안 유효하다. 만료 시각과 같거나 그 이후에는 거부한다.
- 토큰은 DB 저장 없이 검증할 수 있도록 다음 바이트를 연결해 만든다.

  ```text
  [ FF1로 변환한 studyId 8바이트 ][ 만료 시각 4바이트 ][ HMAC-SHA256 앞 8바이트 ]
  ```

- 만료 시각은 UTC 기준 Unix epoch second의 unsigned 4바이트 비트 패턴으로 저장한다. 서명은 변환한 `studyId`와
  만료 시각을 모두 포함한 payload에 대해 계산한다.
- 20바이트를 패딩 없는 URL-safe Base64로 인코딩하므로 토큰은 27자다. 정규 Base64URL 형식, 서명, 만료 시각을
  모두 검증한다.
- 잘못된 형식, 변조, 만료는 모두 `INVALID_INVITE_TOKEN`으로 처리하고 응답 메시지는
  `유효하지 않거나 만료된 초대 토큰입니다.`로 통일한다.
- 기존 22자 토큰에는 만료 시각이 없으므로 새 검증기는 이를 거부한다. 배포 이후에는 초대 링크 API에서 새 링크를
  발급받아야 한다.

이 결정은 초대 토큰의 최대 유효 기간을 정한다. 멤버 방출 즉시 기존 링크를 폐기하지는 않는다. 기존 링크는 발급 후
최대 3일까지 사용할 수 있으며, 즉시 차단이 필요하면 저장 상태나 별도 폐기 버전을 도입하는 결정을 추가로 해야 한다.

## 선택 이유

서명된 토큰에 만료 시각을 포함하면 DB 조회 없이 링크의 유효 기간을 검증할 수 있다. 3일 만료는 기존의 무기한 재사용을
제한하면서, 새 링크를 공유한 뒤 사용할 시간을 제공한다. 만료 시각도 HMAC 입력에 포함해 토큰 소유자가 만료 시각을
바꾸지 못하게 한다.

만료·위조·형식 오류를 하나의 공개 오류로 처리하면 오류 응답만으로 토큰이 과거에 유효했는지를 구분하지 못한다.

## 검토한 대안

### 멤버 방출 시 해당 링크를 즉시 폐기한다

즉시 재가입을 막을 수 있지만 토큰 발급 상태를 저장하거나 스터디별 토큰 버전을 관리해야 한다. 이번 결정은 무기한
유효 기간을 제한하는 데 한정하고, 즉시 폐기는 별도 상태 관리가 필요한 후속 결정으로 둔다.

### 만료 토큰에 별도 오류 코드를 반환한다

클라이언트가 만료와 변조를 다른 방식으로 안내할 수 있지만, 요청자가 토큰의 유효 기간 상태를 더 구체적으로 추측할 수
있다. 현재는 새 링크 요청을 공통 안내로 제공하면 충분하므로 오류 코드를 분리하지 않는다.

## 영향

### 긍정적 영향

- 방출된 멤버가 오래된 초대 링크로 무기한 재가입할 수 있는 상황을 제한한다.
- 토큰 상태 저장과 조회 없이 만료를 검증한다.
- 만료·변조·형식 오류의 API 계약이 하나로 유지된다.

### 부정적 영향과 위험

- 방출 후에도 기존 링크는 발급 시각부터 최대 3일 동안 사용할 수 있다.
- 배포 시점에 기존 22자 링크가 모두 무효화되므로 새 링크 발급이 필요하다.
- 만료 시각이 포함되어 같은 스터디라도 발급 시각이 달라지면 토큰도 달라진다.
- 8바이트 HMAC 태그를 유지하므로 위조 방어 강도는 64비트다.
- unsigned 4바이트 epoch second는 2106년 이후의 시각을 표현할 수 없다.

## 미확정 사항

- 방출 시 기존 링크를 즉시 폐기해야 하는지 여부

## 후속 작업

- 토큰 생성·검증, 만료 경계, 만료 시각 변조를 단위 테스트한다.
- OpenAPI 토큰 길이, 유효 기간, 예시와 오류 메시지를 새 계약에 맞춘다.
- 배포 후 `INVALID_INVITE_TOKEN` 응답 증가와 오래된 링크 사용을 관찰한다.
