# 0060. 앱 롤백 시 DB를 유지하고 이전 앱과 호환되게 마이그레이션한다

- 날짜: 2026-11-05
- 관련 이슈: [#645](https://github.com/woowacourse-teams/2026-ChongChong/issues/645)

## 배경

A/B는 공유 DB를 사용한다. 새 앱 기동 중 Flyway 마이그레이션이 성공하면 트래픽 전환 전에도 DB는 변경될 수 있다.
이후 health 검사가 실패해 이전 앱으로 돌아가더라도 성공적으로 적용된 DB 변경은 자동으로 취소되지 않는다.
따라서 이전 앱을 실행 상태로 남기거나 이미지를 보존하는 것만으로 안전한 롤백을 보장할 수 없다.

## 결정

- 배포 실패 시 앱만 롤백하고 성공적으로 적용된 DB 변경은 유지한다. health 실패를 이유로 DB undo·clean·백업 복원을 자동 실행하지 않는다.
- 일반 무중단 배포의 마이그레이션은 공존하는 이전 앱 및 지원하는 롤백 대상이 읽고 쓸 수 있도록 작성한다. 이미지가 보존됐다는 이유만으로 해당 버전의 복귀를 허용하지 않는다.
- 컬럼 삭제·이름 변경, 타입·제약 변경, enum 등 저장 값의 의미 변경을 호환성 검토 대상으로 삼는다. 추가 변경도 기본값·NOT NULL·기존 INSERT 동작 등에 따라 호환되지 않을 수 있다.
- 호환성을 깨는 변경은 새 구조 추가 → 데이터 이관 및 구/신 앱 공존 → 이전 구조 사용 종료 → 삭제 단계로 나눈다. 공존 중 쓰기와 데이터 일관성을 함께 설계하고, 해당 구버전의 롤백 지원 종료를 확인한 뒤 기존 구조를 제거한다.
- 이미 적용한 Flyway 마이그레이션을 수정하지 않는다. DB 수정은 새로운 버전의 마이그레이션으로 수행한다.
- 호환되지 않거나 검증하지 못한 변경은 일반 자동 롤백 대상에서 제외한다. 별도 배포·복구 계획과 필요 시 점검 시간을 마련한다.

### PR 작성자와 리뷰어의 확인 규칙

1. 스키마뿐 아니라 쿼리, 제약, 저장 값, 데이터 변환, 워커 처리 방식에 변화가 있는지 표시한다. 변화가 없으면 그 근거를 적는다.
2. 관련 변경이 있으면 대상 이전 릴리스를 명시하고, 실제 PostgreSQL 테스트 환경에서 새 마이그레이션 및 새 앱의 쓰기 이후 이전 앱의 주요 읽기·쓰기를 확인한다. 재배포 복귀를 지원한다면 이전 앱의 기동·Flyway 검증도 포함한다.
3. PR에 검증 명령·결과 또는 확인하지 못한 범위를 남긴다. health UP과 Flyway 적용 성공만으로 호환성 검증을 대체하지 않는다.
4. 검증된 릴리스 조합만 구버전 복귀 대상으로 승인한다. 승인 자료를 배포에 전달하는 자동화 방식은 후속 설계로 정한다.

## 선택 이유

서비스 중 DB를 과거 시점으로 복원하면 배포 이후 정상적으로 작성된 데이터까지 영향을 받는다.
DB를 유지하면서 이전 앱이 계속 동작하도록 하면 앱 롤백과 데이터 복구를 분리할 수 있다.
호환성은 장애가 난 순간 판단하기보다 PR 작성과 검증 단계에서 확보한다.

## 검토한 대안

### 앱과 DB를 함께 자동 롤백

버전을 함께 맞출 수 있지만 역방향 데이터 변환과 동시 쓰기를 안전하게 처리해야 한다.
삭제된 데이터 복원도 별도 문제이므로 health 실패의 기본 대응으로 채택하지 않는다.

### DB 변경이 있는 모든 배포를 수동 처리

자동 복귀 위험을 줄이지만 호환 가능한 추가 변경까지 매번 수동 처리해야 한다.
일반 배포는 호환성을 확보하고 예외 변경만 별도 계획으로 다룬다.

## 영향

### 긍정적 영향

- A/B 공존과 앱 롤백에 필요한 DB 조건을 개발·리뷰 과정에서 확인한다.
- 앱 복귀와 DB 데이터 복구의 책임을 구분한다.

### 부정적 영향과 위험

- 구조 변경에 여러 배포와 임시 데이터 동기화 로직이 필요할 수 있다.
- 호환성 테스트를 통과해도 대규모 데이터의 잠금·실행 시간 문제까지 보장하지 않는다.
- DB 자체의 손상과 공유 DB 장애에는 별도 복구 절차가 필요하다.

## 미확정 사항

- 이미지·설정 보존 개수와 기간, 지원할 롤백 대상 범위
- 호환성 결과의 CI 검증 및 배포 승인 자료 전달 방식

## 후속 작업

- AMI 이전 완료 후 실제 배포 경로와 호환성 승인 자료 연계를 점검한다.
- 이미지·설정·Compose를 묶은 이전 릴리스 재배포 절차를 검증한다.
- 이 ADR은 설계 결정 기록이다. 서버·배포 코드 적용과 호환성 실험 완료를 의미하지 않는다.
