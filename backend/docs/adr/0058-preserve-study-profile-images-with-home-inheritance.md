# 0058. 홈 프로필 이미지 변경을 모든 참여 스터디 조회에 함께 반영한다

- 날짜: 2026-11-02
- 관련 이슈: [#622](https://github.com/woowacourse-teams/2026-ChongChong/issues/622)
- 적용 상태: 홈 이미지 변경·초기화와 모든 참여 스터디 조회 반영을 구현했다. File 담당자와 소유자 FK 및 null 소유권 처리는 이든이, 미사용 파일의 DB·S3 삭제는 바니가 담당하기로 합의했다. 전체 회귀·배포 검증은 진행 전이며 스터디별 이미지 수정과 선택 방식은 별도 논의로 남긴다.
- 관련 계약: [홈 이미지 변경·초기화](../openapi/paths/users/profile-image.yaml), [내 프로필 조회·이름 수정](../openapi/paths/users/me.yaml)
- 관련 결정: [ADR-0047](0047-sync-home-name-to-current-study-memberships.md)의 이름 동기화는 유지한다.
  이미지 조회의 홈 반영은 이름 동기화와 구분하며, 파일 처리는 [ADR-0054](0054-separate-upload-verification-from-database-transactions.md)와
  [ADR-0056](0056-issue-notice-image-urls-after-access-check.md)의 공통 기반을 활용한다.

## 배경

`User.profileImageUrl`은 홈 프로필을, `StudyMember.profileImageUrl`은 특정 스터디의 멤버 프로필을 표현한다.
현재 생성·가입은 홈 이미지 URL을 복사한다. 이 분리는 향후 스터디마다 다른 프로필을 설정할 수 있도록 둔 구조다.

이번 작업에서는 홈 이미지 변경·초기화를 홈과 참여 중인 모든 스터디에 함께 반영한다.
스터디별 프로필 수정과 이미지 선택 방식은 현재 구현 범위에서 제외한다. 기존 테이블 분리는 유지한다.
또한 S3 조회용 URL은 만료되므로 현재의 URL 문자열 복사 방식에 그대로 저장할 수 없다.

## 결정

### 현재 홈 이미지를 모든 참여 스터디에서 함께 조회한다

User는 현재 홈 이미지의 기준이다. 내 프로필과 현재 멤버 관련 응답은 해당 User의 홈 이미지를 사용한다.
홈 이미지를 변경하면 모든 참여 스터디의 다음 조회에 새 이미지가 반영되고, 초기화하면 기본 이미지인 null을 반환한다.
새 스터디 생성·가입 후에도 해당 사용자의 현재 홈 이미지를 조회한다.

홈 변경 때 StudyMember의 URL을 일괄 덮어쓰거나 파일 FK·서명 URL을 멤버마다 복사하지 않는다.
기존 이름의 전체 멤버십 동기화는 변경하지 않는다. 스터디별 이미지 수정·선택을 위한 컬럼과 API는 이번에 추가하지 않는다.

### 홈 파일 연결과 기존 외부 URL을 구분한다

- User에 nullable `profile_image_file_id` FK를 추가한다. 한 파일이 여러 사용자의 홈 프로필이 되지 않도록 unique 제약을 둔다.
- 기존 User의 외부 URL은 보존한다. 홈 파일 연결이 있으면 파일이 우선하고, 없으면 기존 외부 URL을 사용한다.
- User와 StudyMember의 분리 및 기존 멤버 URL은 유지한다. 이번 조회 기준은 현재 User의 홈 이미지이며, 멤버 URL을 삭제하거나 분류 이관하지 않는다.
- 활성 프로필 파일을 연쇄 삭제하는 FK 정책을 추가하지 않는다. 사용 중 파일의 삭제 방지는 FK와 파일 사용처 검사로 보호한다.

presigned URL은 어느 프로필에도 저장하지 않는다. User와 StudyMember에 외부 URL을 저장하는 기존 제약과,
응답 시 생성한 서명 URL의 길이는 다른 문제이므로 기존 외부 URL 저장 검증을 서명 URL에 적용하지 않는다.
OpenAPI는 기존 응답 필드명과 string/null 형태를 유지하고 홈 응답 URL의 2,048자 상한을 제거한다.

### 기존 멤버 데이터는 보존하고 조회 기준 변경을 확인한다

현재 생성·가입은 홈 이미지 URL을 멤버에 복사한다. 기존 값은 보존하며 모드 컬럼이나 분류 마이그레이션을 추가하지 않는다.
홈 URL과 멤버 URL이 다른 기존 행은 이번 조회 기준 변경으로 표시가 달라질 수 있으므로 배포 전에 불일치 건수와 원인을 점검한다.
운영 데이터 점검을 이미 수행했다고 가정하지 않는다. 스터디별 이미지 설정과 기존 값의 처리 기준은 별도 논의 항목이다.

### 기존 업로드 완료 흐름으로 홈 파일을 연결한다

클라이언트는 업로드 URL 발급 → S3 PUT → 업로드 완료 API → 홈 이미지 변경 순서로 요청한다.
`uploadPurpose`는 생략하거나 null로 보내 공통 경로를 사용한다. 새 목적 enum이나 studyId를 요구하지 않는다.

`PATCH /api/users/me/profile-image`는 필수 양수 fileId를 받는다. 새 파일의 본인 소유·COMPLETED·이미지 정책·미사용 여부를
검증한 뒤 연결한다. 기본 정책은 JPEG/PNG/WebP 한 장, 0바이트 초과·최대 5MiB이며 형식·용량은 설정으로 관리한다.
공통 업로드 용량 제한도 적용하고, 형식 설정을 바꿀 때는 공통 이미지 URL 생성기의 지원 형식도 함께 고려한다.
형식 검증은 메타데이터의 Content-Type 기준이며 실제 파일 바이트 검사와 구분한다.

현재 홈 파일과 같은 ID를 다시 지정하면 소유권과 완료 상태를 확인하고 기존 연결을 유지한다.
새 파일에 적용하는 미사용·이미지 정책 검사 때문에 현재 파일의 재지정을 거부하지 않는다.
이름은 바꾸지 않으며 현재 홈 이름과 이미지 URL을 기존 UserProfileResponse 형태로 반환한다.

`DELETE /api/users/me/profile-image`는 홈 파일 연결과 외부 URL을 함께 해제한다. 소셜 이미지로 복원하지 않는다.
홈과 현재 참여 중인 모든 스터디의 해당 사용자 이미지는 이후 null을 반환한다. 반복 초기화도 본문 없이 204다.
재로그인으로 소셜 프로필을 다시 덮어쓰지 않는 기존 로그인 정책도 유지한다.

### 사용자·파일 잠금과 공통 사용처 검사를 함께 적용한다

홈 변경·초기화는 하나의 DB 트랜잭션에서 사용자 행을 먼저 쓰기 잠금으로 조회한다.
기존 이름 수정·스터디 생성·가입과 같은 사용자 잠금 기준을 사용한다. 멤버 행을 일괄 갱신하지 않는다.
연결을 교체·해제할 기존 파일과 새 파일의 잠금이 필요하면 중복을 제거하고 파일 ID 오름차순으로 획득한다.
상태·소유권·사용처는 파일 잠금 이후 확인하며, 잠금 전 영속성 컨텍스트의 오래된 값을 그대로 사용하지 않도록 검증한다.
홈 이미지 변경·초기화는 공통 단건 파일 잠금의 개별 대기 제한 3초를 사용한다. 파일 잠금 시간 초과 시 변경을 롤백하고
기존 공통 FILE_UPLOAD_BUSY 오류로 503을 반환한다. 사용자는 잠시 후 같은 요청을 다시 시도할 수 있다.

`existsAnyUsageByFileId`에 홈 프로필 사용 여부를 추가한다. 프로필뿐 아니라 공지·과제·제출물·스터디 이미지 연결 경로도
같은 파일 잠금과 검사를 사용해 동시 중복 연결을 막는다. 멤버 관련 조회는 User의 연결을 통해 파일을 사용한다.

새 파일 연결 실패 시 프로필 변경은 롤백한다. 선행 완료 API의 COMPLETED 상태는 되돌리지 않는다.
교체·초기화로 분리한 파일은 COMPLETED로 보존하며 요청 중 S3 HEAD·완료 전환·물리 삭제는 수행하지 않는다.
미사용 S3 삭제 배치를 이번 기능 안에 새로 만들지 않고 [#531](https://github.com/woowacourse-teams/2026-ChongChong/issues/531)과 연계한다.

### 기존 탈퇴·제출물 삭제 정책을 유지하고 프로필 정리 범위를 구분한다

제출물 삭제 여부는 이번 프로필 기능에서 새로 바꾸지 않는다. 사용자는 현재 구현을 유지하기로 확인했다.
[ADR-0024](0024-use-database-cascades-for-hard-delete.md)는 멤버 삭제 시 제출물 CASCADE와 공지·과제 원본 보존을,
[ADR-0034](0034-delete-user-account-in-one-transaction.md)는 계정 탈퇴 시 해당 멤버십과 제출물의 삭제를 정한다.
따라서 기존 제출물 삭제를 유지하고, 프로필을 소속 주체에 맞춰 정리하는 규칙을 추가한다.
사용자 또는 멤버십이 없어졌다는 이유만으로 해당 사용자가 올린 모든 파일을 일괄 삭제하지 않는다.

| 삭제 상황 | 제출물·멤버 프로필 데이터 | 홈 프로필 | 공지·과제 |
| --- | --- | --- | --- |
| 스터디 탈퇴·방출 | 해당 멤버의 제출물과 종속 첨부 관계, 멤버 프로필 데이터를 제거 | 유지. 다른 참여 스터디 조회에서도 계속 사용 | 보존 |
| 계정 회원 탈퇴 | 모든 멤버십의 제출물·종속 첨부 관계·멤버 프로필 데이터를 제거 | 홈 프로필 및 파일 연결 제거 | 스터디가 유지되면 원문과 첨부 보존 |

현재 리더의 계정 탈퇴를 막는 기존 정책은 유지한다. 스터디 자체를 삭제할 때 스터디 원문을 정리하는 기존 정책도 변경하지 않는다.
[ADR-0057](0057-reference-comment-resources-by-type-and-id.md)에 따라 삭제된 제출물의 댓글·관련 알림도 정리하고,
원문이 남은 댓글은 작성자가 탈퇴해도 보존하며 탈퇴자 이름과 기본 이미지로 표시한다. 이 댓글 정책도 변경하지 않는다.
외부 소셜 이미지 URL은 연결만 해제하며 외부 서비스의 이미지를 삭제하지 않는다.

제출물·프로필의 도메인 데이터와 연결은 탈퇴 트랜잭션에서 제거하고, 해당 업로드 파일은 실제 사용처가 없어졌는지 확인한 뒤
미사용 정리 대상으로 처리한다. 실제 S3 삭제는 정리 작업과 연계한다. 공지·과제 등 보존된 리소스가 사용하는 파일의
메타데이터·S3 객체는 소유자의 탈퇴 후에도 유지한다. 소유자가 없다는 사실만으로 미사용 파일로 판정하지 않는다.

file_metadata.owner_id는 nullable로 변경하고 FK에 ON DELETE SET NULL을 적용한다.
사용자 물리 삭제와 같은 DB 트랜잭션에서 소유자 연결만 해제하고 파일의 상태·메타데이터·S3 객체는 보존한다.
사용 중인 파일을 탈퇴만으로 DELETE_PENDING으로 바꾸지 않는다. 미사용 파일의 삭제 대상 판별과 상태 전환·실제 삭제는 정리 작업이 담당한다.
이 경우 신규 파일 생성에는 여전히 로그인한 소유자를 요구하고, 소유자가 없는 기존 파일의 완료·신규 연결은 허용하지 않는다.
파일 소유권 검사는 null 소유자를 본인 소유로 판단하지 않고 FILE_NOT_OWNED로 거절한다. 업로드 완료 전 snapshot은 LEFT JOIN으로
소유자가 없는 파일도 반환하며, S3 확인 이후 완료 저장 단계에서도 null 소유권을 재검증한다. 기존 리소스의 권한 있는 조회는 유지한다.
FK·공통 File의 null 소유권 처리는 이든이, 실제 미사용 file_metadata·S3 삭제는 바니가 담당한다.
기존 V22에서 자동 생성된 FK 이름이 PostgreSQL과 H2에서 다르므로 V30 Java migration이 JDBC 메타데이터로 해당 FK를 찾아 교체한다.
적용된 과거 migration을 수정하지 않는다.

### 리소스 권한 확인 후 선택한 이미지의 URL을 생성한다

현재 공통 `FileUrlGenerator.generateImageUrl`을 재사용한다. 프로필 이미지 해석은 작은 협력 객체가 담당하고,
엔티티·DTO는 S3 생성기를 직접 호출하지 않는다. 홈과 스터디 서비스를 서로 호출하는 순환 의존을 만들지 않는다.

내 프로필 조회와 이름 수정 응답은 홈 이미지를 사용한다. 멤버 목록·공지 읽음 현황·제출 현황·제출물 목록/상세·댓글은
해당 StudyMember와 연결된 User의 현재 홈 이미지를 사용한다. 기존 인증·스터디 소속·제출물 공개 범위를 확인한 뒤 URL을 생성한다.
스터디를 떠난 댓글 작성자는 현재 홈 이미지가 있어도 기존처럼 탈퇴자 이름과 null 이미지로 표시한다.

목록은 필요한 홈 이미지 원본 정보를 projection 또는 배치로 조회해 멤버마다 쿼리를 추가하지 않는다.
동일 응답에서 같은 이미지 원본의 서명 결과는 재사용할 수 있다.

조회 URL은 공통 aws.s3.url-validity(기본 10분, AWS_URL_VALIDITY로 변경)를 따른다.
만료 시 해당 리소스를 재조회하며 같은 시각에 발급한 URL이 반드시 다른 문자열이라는 보장은 두지 않는다.
변경 후 프론트는 관련 조회 캐시를 갱신한다. 이미 표시된 화면을 실시간으로 갱신하는 전송 기능은 추가하지 않는다.

## 선택 이유

홈 변경을 모든 참여 스터디에 함께 반영한다는 현재 요구를 구현하고, 홈 변경 시 여러 멤버 행을 덮어쓰지 않는다.
스터디별 프로필 설계를 미리 확정하지 않고 기존 테이블과 멤버 URL을 보존한다. 파일 연결을 저장하면 URL 만료가 영속 데이터에 전파되지 않는다.
기존 업로드·완료·조회 생성기와 사용처 검사를 재사용해 파일 검증 및 중복 연결 정책을 일관되게 유지한다.

## 검토한 대안

### 홈 변경 때 모든 멤버에 URL을 복사한다

기존 조회 코드를 유지할 수 있지만 홈 변경마다 여러 행을 갱신해야 하고 서명 URL을 복사하면 만료된 값을 저장하게 된다.
현재 User를 기준으로 조회하는 방식을 사용한다.

## 영향

### 긍정적 영향

- 홈 변경·초기화가 모든 참여 스터디의 다음 조회에 함께 반영된다.
- 기존 소셜 이미지와 멤버 URL 및 테이블 분리를 보존한다.
- 현재 파일 상태·사용처 검사·조회 URL 생성 기반과 기존 응답 필드를 재사용한다.

### 부정적 영향과 위험

- 여러 도메인의 이미지 조회와 projection을 변경하고 조회 성능을 검증해야 한다.
- 기존 홈/멤버 URL이 다르면 표시가 달라질 수 있어 배포 전 데이터 점검이 필요하다.
- URL 만료와 프론트 캐시 갱신을 처리해야 한다. 이미 발급한 URL의 즉시 철회는 보장하지 않는다.
- 파일 소유자 연결 해제와 소유권 검사를 함께 수정하지 않으면 사용자 FK가 탈퇴를 막거나 null 소유자를 처리하지 못할 수 있다.

## 미확정 사항

- 운영 데이터의 홈/멤버 URL 불일치 건수와 원인은 아직 확인하지 않았다. 조회 기준 변경 전 점검 항목이다.
- 스터디별 이미지 수정과 선택 방식은 팀과 별도로 결정하며 이번 구현에 포함하지 않는다.
- 실제 파일 내용 검사와 미사용 파일 정리의 실행 시점은 공통 File 작업에서 조율한다. 미사용 정리는 바니가 담당하며 홈 프로필 사용처를 포함해야 한다. 기존 완료 API가 바이트 형식을 검증한다고 가정하지 않는다.

## 후속 작업

- V30과 null 소유권 처리를 함께 배포한다. 미사용 파일 정리는 별도 File 작업으로 연계하고 계정 탈퇴 시 사용 중인 파일이 삭제되지 않는 정책을 유지한다.
- 스터디 하나의 탈퇴·방출로 홈 이미지나 다른 스터디 이미지가 사라지지 않는지, 소유자가 없는 보존 파일의 조회·신규 연결 제한을 검증한다.
- 홈 파일 연결을 기반으로 이미지 정책·사용처 검사와 변경·초기화 API를 구현한다.
- 홈 변경·초기화와 조회 경로를 작은 단위로 연결하고, 모든 참여 스터디 반영·신규 가입·탈퇴자 마스킹을 검증한다.
- 동일 파일 재요청·잘못된 파일·동시 연결·실패 롤백·기본 이미지 반복 초기화·파일 보존·목록 쿼리를 검증한다.
- 전체 backend·OpenAPI 검증 및 dev 브라우저 업로드·실제 이미지 조회 확인 후 구현 상태를 갱신한다.
