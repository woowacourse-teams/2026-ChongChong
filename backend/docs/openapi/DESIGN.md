# 백엔드 개발 보드 디자인

## 1. 목적과 기준
사용자가 제공한 Notion 데이터베이스 화면처럼 한 화면에서 많은 API를 비교한다.
참고 대상은 촘촘한 행, 독립 열, 옅은 세로 구분선, 파스텔 태그다. Notion 앱 창이나 원본 데이터는 복제하지 않는다.

## 2. 화면 구조
작은 문서 탐색 → 제목 → 전체 API 수 → 데이터베이스 표.
큰 통계 영역, 카드 배경, 긴 소개 문장은 두지 않는다.
메서드 / 이름 / 개발 설명 / URI / 상태 / 담당자의 여섯 열로 구성한다.
행 높이는 개발 설명 길이에 맞춘다. 긴 경로는 셀 안에서 줄바꿈하며 좁은 화면의 표는 가로 스크롤해 읽는다.
개발 설명은 이름 바로 다음 열에 항상 표시하며 셀 안에서 줄바꿈된다.

## 3. 토큰
- 캔버스 #ffffff, 본문 #37352f, 보조 #78766f, 경계 #e9e9e7, hover #f7f7f5, focus #2878b8.
- GET: #f4e4bc / #715621, POST: #f5dce6 / #813d58, PATCH·PUT: #e8ddf5 / #654883, DELETE: #dce9df / #35634a.
- 상태 완료: GET 색, 진행: #d8e8f9 / #285a89, 리뷰: PATCH 색, 대기·미확인: #efeeec / #615d59.
- 글꼴: 시스템 한글 sans-serif. 크기 12/13/14/15/24px, 줄높이 1.5.
- 간격 4/8/12/16/24/32px. 반경 태그 4px, 버튼 6px. 그림자 없음.
- 최대 콘텐츠 너비 1760px, 표 최소 너비 1160px. 데스크톱 좌우 여백 32px.

## 4. 반응형
760px 이하에서는 카드형 행으로 재배치한다. 이름·메서드·URI·상태·담당자·설명을 모두 제공한다.
태블릿은 가로 스크롤 가능한 표를 사용하며 영역에 이름과 키보드 포커스를 제공한다.

## 5. 요소와 상태
- 제목 링크: 기본 본문 색, hover 밑줄, focus outline.
- 메서드/상태: 작은 직사각형 파스텔 태그. 텍스트로 의미를 함께 전달한다.
- 담당자: 이니셜 원과 GitHub 아이디. 사진이나 실명은 임의로 넣지 않는다.
- 개발 설명: 항상 표시. 기존 줄바꿈, 후속 작업 구분, HTML escaping 유지.
- 상태 기준: 접을 수 있는 보조 안내. 상태별 통계 없이 전체 API 수만 제공한다.

## 6. 접근성
명시적 table/rowgroup/row/cell 역할, focus outline, 의미 있는 summary 유지.
가로 스크롤과 상태 기준 안내는 키보드로 조작 가능하다. 모바일 경로는 줄바꿈한다.

## 7. 검증
375/768/1280 너비, 설명 표시와 문서 이동을 확인한다.

## 8. 데이터 경계
현재 OpenAPI 데이터와 상태를 유지한다. 권한이나 버전은 스크린샷에서 추정해 추가하지 않는다.
삭제 요청한 PR 근거와 개인 기여 문장은 다시 표시하지 않는다.
