# 과제·제출물 첨부 계약

## 업로드와 연결

업로드 URL 발급 → S3 PUT → 업로드 완료 API(#544, PR #550) → 과제·제출물 저장 순서로 호출한다.
이 기능은 COMPLETED 파일만 연결하며 S3 검증이나 완료 상태 전환을 다시 수행하지 않는다.
PR #550이 반영된 dev를 통합했으며 완료 API 이후 과제·제출물 첨부 연결을 HTTP 테스트로 검증한다.

생성·수정 요청의 `attachmentFileIds`는 표시 순서를 포함한 최종 목록이다.
생략 또는 null은 유지, 빈 배열은 전체 제거다. 새 파일은 요청자 소유이며 다른 공지·과제·제출물에
연결되지 않은 파일이어야 한다. 기존 파일은 소유자가 달라도 과제 수정 권한이 있으면 유지할 수 있다.
같은 파일을 여러 곳에 연결하지 못하도록 파일 행을 ID 순서로 잠근 뒤 연결 여부를 확인한다.
과제 행은 일반 조회하며, 제출 등록 시 기존 제출 행 잠금과 파일 연결 시 파일 행 잠금을 사용한다.
과제 삭제와 제출이 겹쳐 생기는 미연결 파일은 후속 고아 정리에서 처리한다.
고아 정리는 유예 시간이 지난 COMPLETED 파일도 실제 연결 여부를 확인해야 하며, 이 변경에는 포함하지 않는다.

기본 제한은 파일당 5MiB, 최대 10개다. 크기는 공통 `file.upload.max-size-bytes` 설정을 사용한다.
허용 MIME은 JPEG, PNG, WebP, PDF, plain text, ZIP, DOCX, PPTX이며
`assignment.attachments.allowed-content-types`, `assignment.attachments.max-count`로 변경할 수 있다.
MIME은 저장된 메타데이터 기준이며 파일 내부 형식 검사나 악성 파일 검사는 포함하지 않는다.

## 제출 내용

과제별 제출 형식 제한 없이 텍스트·링크·이미지·파일을 조합해서 제출한다.
제출 방법 안내문 `submissionMethod`는 그대로 유지한다.
제출·수정 결과에는 텍스트, 링크 또는 첨부파일이 하나 이상 있어야 한다.
POST 재제출에서 content/link를 생략하거나 null로 보내면 기존 값을 null로 덮어쓴다.
PATCH 수정에서 content/link를 생략하거나 null로 보내면 유지하며 빈 문자열을 보내면 비운다.
POST에서 content/link를 생략하고 attachmentFileIds를 빈 배열로 보내면 EMPTY_SUBMISSION으로 거부한다.
첨부를 모두 제거하는 경우에도 최종 결과에 텍스트나 링크가 남아야 한다.

## 조회와 삭제

과제 상세, 내 제출, 제출물 상세는 파일 ID·이름·MIME·크기·표시 순서를 반환한다.
첨부 정보는 기존 상세 조회의 스터디 소속·공개·소유권 검사 이후 반환한다.
JPEG·PNG·WebP 첨부는 `imageUrl`에 S3 GET 서명 URL을 반환한다. 프론트는 이 URL을 이미지 src로 사용한다.
일반 문서는 `imageUrl`이 null이며 파일명·크기·contentType으로 파일 아이콘을 표시한다. 문서 다운로드는 포함하지 않는다.
URL은 상세 조회 권한 확인 후 발급하며 `aws.s3.url-validity` 동안 유효하다. 만료되면 상세 조회로 갱신한다.
이미 발급한 URL은 권한 변경 후에도 만료 전까지 사용할 수 있으므로 응답과 URL을 공개 캐시에 저장하지 않는다.
운영 서명 주체에는 해당 객체의 s3:GetObject 권한이 필요하다. 버킷 공개 설정은 필요하지 않다.

첨부 제거, 과제 삭제, 리더 제출 대상 해제 시 모두 연결만 제거하고 파일은 COMPLETED 상태로 유지한다.
후속 고아 정리는 미연결 상태에 유예 시간을 두고 실제 연결 여부를 다시 확인한 뒤 삭제하는 방향으로 진행한다.
구체적인 유예 시간과 구현은 별도 이슈에서 결정한다.
실제 S3 삭제는 공통 정리 작업의 책임이며 이 구현에서 수행하지 않는다.
스터디 삭제·회원 탈퇴 등 DB cascade로 생기는 미연결 파일은 공통 고아 정리 작업에서 함께 다뤄야 한다.

## 검증

PostgreSQL 컨테이너와 실제 HTTP 요청으로 첨부 교체·순서·삭제, 소유권·형식·개수·크기 거부,
혼합 형식 제출, 공개 정책별 첨부 정보 조회 권한, 같은 파일에 대한 동시 연결을 검증한다.
S3 메타데이터 조회는 HTTP 테스트에서 대체하며 실제 AWS 업로드 통신은 검증하지 않는다.
