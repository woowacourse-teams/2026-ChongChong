# 댓글 정책

2026-10-30까지 사용자와 확정한 댓글 제품 정책을 기록한다.
이 문서는 댓글 기능의 구현 완료를 의미하지 않는다. 남은 결정은 미확정 사항에 명시한다.

## 댓글 범위

공지, 과제, 제출물에 텍스트 댓글을 작성할 수 있다.
답글, 이미지·파일 첨부, 서식 편집은 초기 범위에서 제외한다.

## 댓글 본문

- 앞뒤 공백을 제거한 뒤 1~1,000자로 제한한다.
- 공백만 있는 댓글은 거부한다.
- 본문 안의 공백과 줄바꿈은 유지한다.

## 댓글 표시와 목록 조회

댓글에는 작성자의 이름, 프로필 이미지, 작성 시각, 내용을 표시한다.
수정된 댓글에는 `수정됨`을 표시한다.
스터디를 탈퇴하거나 방출되었거나 회원 탈퇴한 작성자는 이름 대신 `탈퇴한 스터디원`, 프로필 이미지 대신 기본 이미지를 표시한다.

댓글은 작성 시각이 오래된 순서로 조회하며, 한 번에 조회하는 기본 개수는 10개로 한다.
댓글을 수정해도 작성 시각에 따른 목록 순서는 유지한다.

## 조회와 작성 권한

댓글 조회·작성 권한은 댓글 대상의 조회 권한을 따른다.

| 댓글 대상 | 조회·작성 가능 대상 |
| --- | --- |
| 공지 | 해당 스터디의 모든 스터디원 |
| 과제 | 해당 스터디의 모든 스터디원 |
| 공개 제출물 | 해당 제출물을 조회할 수 있는 스터디원 |
| 비공개 제출물 | 제출자와 해당 스터디의 리더 |

### 작성 가능 시점

과제 마감 이후에도 과제와 제출물에 새 댓글을 작성할 수 있다.
제출물 댓글은 실제 제출이 완료된 후부터 작성할 수 있다.
제출 대상이 정해졌더라도 실제 제출 이전에는 해당 제출물에 댓글을 작성할 수 없다.

## 수정·삭제 권한

댓글 작성자는 자기 댓글을 수정·삭제할 수 있다.
리더는 다른 사람이 작성한 댓글도 삭제할 수 있다.
다른 사람의 댓글 내용은 리더도 수정할 수 없다.

## 삭제와 탈퇴

공지·과제·제출물이 삭제되면 그 아래 댓글과 해당 댓글의 관련 알림도 함께 삭제한다.
과제 삭제로 하위 제출물이 삭제되는 경우에는 해당 제출물의 댓글도 삭제 대상에 포함한다.
이미 기기에 전달된 푸시는 회수하지 못한다.

스터디 탈퇴·방출 또는 회원 탈퇴 이후에도 댓글 대상이 남아 있으면 작성 댓글을 유지하고 표시한다.
작성자 본인과 다른 사람이 작성한 댓글 모두 원문이 남아 있는 한 유지한다.
탈퇴자의 제출물 자체가 삭제되면 그 안에 작성된 댓글은 작성자와 관계없이 함께 삭제한다.
작성자가 누구인지와 관계없이 원문 삭제 정책을 우선한다.

개별 댓글을 삭제하면 댓글 데이터와 해당 댓글의 관련 알림도 완전히 삭제한다.
삭제된 댓글의 본문이나 별도의 삭제 표시를 남기지 않는다.

회원 탈퇴 시에도 작성 댓글을 보존하며, 다른 수신자가 받은 해당 댓글의 관련 알림도 유지한다.
탈퇴한 사용자 본인이 수신한 알림은 기존 회원 탈퇴 정책에 따라 정리한다.
회원 탈퇴로 제출물 자체가 삭제되면 그 제출물의 모든 댓글과 관련 알림을 함께 삭제한다.

## 새 댓글 알림

### 발생 시점과 수신자

새 댓글 등록에만 알림을 생성한다.
댓글 수정·삭제 기능을 지원하더라도 수정·삭제 알림은 보내지 않는다.
새 댓글마다 수신자별로 별도 알림을 생성하며, 여러 댓글을 하나의 알림으로 묶지 않는다.

| 댓글 대상 | 알림 수신 후보 |
| --- | --- |
| 공지·과제 | 댓글 등록 시점의 해당 스터디 모든 리더 |
| 제출물 | 해당 제출물의 제출자 |

수신 후보에는 다음 공통 규칙을 적용한다.

- 이번 댓글 작성자 본인은 제외한다.
- 수신 대상 선정 시점에 댓글 대상의 조회 권한이 있는 사람만 포함한다.
- 여러 조건에 해당하는 사용자도 같은 댓글에 대한 알림은 한 번만 받는다.

공지·과제 알림의 리더는 특정 작성자가 아니라 해당 스터디의 모든 리더를 의미한다.
제출물에서는 리더라는 이유만으로 수신 후보에 추가하지 않는다.
리더도 해당 제출물의 제출자일 때만 수신 후보가 된다.
기존 댓글 작성자에게는 댓글 참여를 이유로 알림을 보내지 않는다.
기존 댓글 작성자까지 알림을 확대하는 정책은 추후 검토한다.
알림 범위를 확대할 때 원문별 댓글 알림 끄기 기능도 함께 검토한다.

### 알림 문구

| 항목 | 형식 | 예시 |
| --- | --- | --- |
| 제목 | `[{스터디 이름}] 새 댓글` | `[총총 스터디] 새 댓글` |
| 내용 | `{댓글 작성자 이름} 스터디원이 댓글을 달았어요` | `바니 스터디원이 댓글을 달았어요` |

알림 문구에는 원문 제목이나 댓글 본문을 넣지 않는다.
알림을 누르면 댓글이 속한 원문을 열고, 해당 알림이 가리키는 댓글 위치로 이동한다.

### 전달 방식

앱 내 알림을 저장하고, Web Push를 허용한 기기에도 전달한다.
Web Push를 허용하지 않은 사용자도 앱 내 알림을 확인할 수 있다.

### 원문 조회 권한 변경

공개 범위 변경 등으로 원문 조회 권한을 잃은 사람의 기존 댓글 알림을 삭제한다.
해당 알림에 연결된 전송 대기 중인 Web Push도 함께 삭제한다.
이미 기기에 전달된 푸시는 회수하지 못한다.

## 기존 설계와의 관계

- [ADR 0024](adr/0024-use-database-cascades-for-hard-delete.md)는 공지·과제를 특정 멤버가 아닌
  스터디의 데이터로 관리하며 작성자 관계를 두지 않는다. 이번 알림 정책도 특정 공지·과제 작성자를 식별하지 않는다.
  사용자나 스터디 멤버가 하드 삭제되더라도 원문이 남은 댓글은 보존해야 하므로,
  댓글의 작성자 연결과 표시 정보 보존 방식은 기존 사용자·멤버 삭제 경로를 고려해 기술 설계에서 결정한다.
- 알림 저장과 Web Push 전달의 기존 분리는
  [ADR 0038](adr/0038-separate-logical-notifications-and-web-push-delivery.md)을 따른다.
- [ADR 0045](adr/0045-delete-notifications-with-resources.md)는 원본 자원 삭제 시 관련 알림을
  함께 삭제하도록 정한다. 이번 정책도 댓글 대상 삭제 시 댓글과 관련 알림을 함께 삭제한다.

## 미확정 사항

없음. 댓글 보존 방식과 기존 사용자·멤버 삭제 처리의 연결은 후속 기술 설계에서 구체화한다.
